# Abacus Curriculum

이 문서는 주산 훈련 난이도 구현 전에, 앱의 문제 생성과 훈련 스테이지가 참고할 커리큘럼 구조를 정리한다. 실제 문제 생성기 구현은 다음 단계로 남기고, 여기서는 stage id와 생성 전략 방향을 정의한다.

이 커리큘럼은 주산수리셈 교재 흐름을 참고한 앱용 초안이다. 실제 주산 지도 커리큘럼을 확정한 것이 아니며, 아이의 실제 교재 진도와 학습 반응에 따라 stage 순서와 문제 생성 조건은 계속 수정한다. 초기 구현은 MVP 범위의 단순 단계만 반영하고, 5의 보수/10의 보수/암산/급수형 문제는 추후 검증 후 확장한다.

## 1. 설계 원칙

- 난이도는 단순 `easy / normal / hard`보다 교재 단계 기반 `stage id`로 관리한다.
- 한 stage는 하나의 명확한 학습 목표만 가진다.
- 예: `받아올림 없는 4까지 덧셈·뺄셈`, `10을 활용한 +9 덧셈`
- 아이가 막히면 같은 stage를 반복할 수 있어야 한다.
- 문제 생성기는 완전 랜덤이 아니라 stage별 의도된 패턴을 생성해야 한다.
- Bluetooth 주판 입력/정답 확인 구조와 충돌하지 않아야 한다.
- 화면/보상/저장 구조는 stage id를 기준으로 추후 확장할 수 있어야 한다.

## 2. 부모 설정과 앱 사용 흐름

이 앱은 주산을 처음부터 모두 가르치는 교재 대체 앱이라기보다, 아이가 주산수리셈 교재를 한 권씩 학습한 뒤 해당 단계의 문제를 게임에서 반복·심화·복습하는 구조를 우선한다.

- 부모에게는 `S1-01`, `S1-02` 같은 세부 stage id를 기본으로 노출하지 않는다.
- 부모 설정 화면에는 아이가 실제로 배우는 책 진도에 맞춰 `1단계`~`10단계` 교재 단위만 노출한다.
- 세부 stage id는 내부 문제 생성, 개발자 모드, 추후 자동 추천용으로 사용한다.
- 예: 부모가 `1단계`를 고르면 앱 내부에서는 `S1-01`~`S1-07` 같은 stage를 기준으로 문제를 생성하거나 추천한다.
- 아이가 실제 교재에서 배우는 단계와 앱의 선택 단계를 맞추는 것이 기본 흐름이다.
- 나중에는 아이의 수행 결과, 오답 패턴, 반복 횟수를 바탕으로 같은 교재 단계 안에서 세부 stage를 자동 추천할 수 있다.
- 지금은 자동 추천/부모 리포트를 구현하지 않고, 부모가 교재 단계를 직접 선택하는 단순 구조를 우선한다.

## 3. 교재 참고 기반 큰 흐름

주산수리셈 교재와 문화센터 강의 흐름은 초반부터 수 범위와 연산 패턴을 매우 세밀하게 쪼갠다. 앱도 이 흐름을 참고하되, 교재를 그대로 복사하지 않고 문제 생성에 적합한 stage 단위로 재구성한다.

### 기초 단계

- 주판 명칭/구조/자리수 익히기
- 0~5 수 놓기
- 6~10 수 놓기
- 숫자 읽기
- 자리값 익히기
- 주판알 움직임 익히기

### 1단계

- 수 개념과 9까지의 수
- 받아올림 없는 4까지 덧셈·뺄셈
- 받아올림 없는 5까지 덧셈·뺄셈
- 받아올림 없는 6~7까지 덧셈·뺄셈
- 받아올림 없는 8~9까지 덧셈·뺄셈
- 받아올림 없는 한 자리 덧셈·뺄셈 3행

### 2단계

- 수 가르기와 모으기
- 50까지의 수
- 받아올림 있는 한 자리 수 덧셈
- 받아올림 없는 한 자리 수 덧셈·뺄셈 3행

### 3단계

- 여러 가지 모양과 100까지의 수
- 5를 활용한 한 자리 수 덧셈
- 10을 활용한 한 자리 수 덧셈
- 받아올림 있는 한 자리 수 덧셈·뺄셈 3행

### 4단계

- 시계 보기와 더하기/빼기
- 50이 되는 한·두 자리 수 덧셈
- 100이 되는 한·두 자리 수 덧셈
- 한 자리 수 덧셈·뺄셈 4행

### 5단계

- 도형 움직이기
- 두 자리 수 덧셈·뺄셈
- 10을 활용한 한·두 자리 수 덧셈·뺄셈

### 이후 단계

- 두 자리 수 연속 계산
- 세 자리 수 계산
- 곱셈/나눗셈
- 암산 전환
- 속도 훈련
- 급수형 문제

## 5. LevelConfig / StageConfig 타입 방향

부모 설정에는 교재 단계 단위의 `AbacusLevelConfig`를 사용하고, 실제 문제 생성에는 세부 `AbacusStageConfig`를 사용한다.

```ts
type AbacusLevelConfig = {
  level: number;
  title: string;
  summary: string;
  stageIds: string[];
  status: 'mvp' | 'planned' | 'later';
  defaultStageId?: string;
};
```

나중에 `src/config/abacusStageConfig.ts` 또는 `src/data/abacusStages.ts`로 옮길 수 있는 타입 방향이다.

```ts
type AbacusOperation = 'add' | 'subtract';
type ComplementType = 'none' | 'five' | 'ten' | 'mixed';

type AbacusStageConfig = {
  id: string;
  title: string;
  textbookLevel: string;
  objective: string;
  digitCount: 1 | 2 | 3;
  numberCount: number;
  operations: AbacusOperation[];
  maxNumber: number;
  minResult: number;
  maxResult: number;
  allowCarry: boolean;
  allowBorrow: boolean;
  complementType: ComplementType;
  complementFocus?: string;
  rowCount: 2 | 3 | 4 | 5;
  problemCountPerSet: number;
  rewardMultiplier: number;
  fatigueMultiplier?: number;
  generatorStrategy: string;
};
```

예시:

```ts
const stage: AbacusStageConfig = {
  id: 'S1-01',
  title: '받아올림 없는 4까지 덧셈',
  textbookLevel: '1단계',
  objective: '4 이하 범위에서 받아올림 없는 덧셈을 익힌다.',
  digitCount: 1,
  numberCount: 2,
  operations: ['add'],
  maxNumber: 4,
  minResult: 0,
  maxResult: 4,
  allowCarry: false,
  allowBorrow: false,
  complementType: 'none',
  rowCount: 2,
  problemCountPerSet: 10,
  rewardMultiplier: 1,
  generatorStrategy: 'no-carry-add-within-4',
};
```

## 6. 문제 생성 전략

문제 생성기는 stage별 목표 패턴을 보장해야 한다. 완전 랜덤 문제를 만든 뒤 필터링하는 방식보다, stage config의 generator strategy가 직접 유효한 후보를 생성하는 방식이 안정적이다.

### 받아올림 없는 덧셈

- 각 자리 합이 9 이하가 되도록 생성한다.
- S1 초반에서는 최대 결과를 4, 5, 7, 9처럼 단계별로 제한한다.
- 예: `S1-01`은 `a + b <= 4`를 만족해야 한다.

### 받아내림 없는 뺄셈

- 중간 결과가 음수가 되지 않도록 생성한다.
- 한 문제 안에서 여러 번 빼는 경우에도 매 step 결과가 0 이상이어야 한다.
- 초반 stage에서는 시작 수와 뺄 수 있는 수의 범위를 좁게 둔다.

### +9, +8, +7 보수 단계

- 단순 랜덤이 아니라 해당 패턴이 반드시 나오게 생성한다.
- 예: `S2-02`는 `+9`가 포함되어야 한다.
- `+9`는 `+10 -1`, `+8`은 `+10 -2`처럼 10의 보수 사고를 유도한다.
- 문제 표시에는 일반 덧셈으로 보이되, generator metadata에는 `complementFocus: '+9'`를 남길 수 있다.

### 5의 보수 단계

- `+4`, `+3`, `+2`, `+1`이 5의 보수 조작으로 이어지는 패턴을 생성한다.
- 5를 활용하는 stage에서는 `complementType: 'five'`로 표시한다.

### 3행/4행 문제

- 여러 숫자를 순서대로 더하거나 뺀다.
- 한 문제 안에서 중간 결과가 음수가 되지 않아야 한다.
- row 수가 늘수록 피로도와 보상을 다르게 둘 수 있다.
- Bluetooth 입력은 최종 답 제출만 받되, 문제 데이터에는 계산 행을 순서대로 보관한다.

### 주판 조작 우선

- 종이 계산으로는 가능해도 실제 주판 조작이 너무 건너뛰는 문제는 피한다.
- 초반 stage에서는 자리 이동, 보수 조작, 받아올림/받아내림을 한 번에 섞지 않는다.
- 한 stage 안에서는 한 가지 새로운 조작만 강조한다.

## 7. MVP 실제 구현 범위

모든 stage를 한 번에 구현하지 않는다. 우선 문제 생성기와 훈련장 UI에 연결할 stage는 아래 범위로 제한한다.

### MVP 1차

- `B0-02`: 0~5 수 놓기 또는 숫자 입력 확인
- `S1-01`: 받아올림 없는 4까지 덧셈
- `S1-02`: 받아올림 없는 4까지 뺄셈
- `S1-03`: 받아올림 없는 4까지 덧셈·뺄셈 혼합
- `S1-04`: 받아올림 없는 5까지 덧셈·뺄셈
- `S1-05`: 받아올림 없는 6~7까지 덧셈·뺄셈
- `S1-06`: 받아올림 없는 8~9까지 덧셈·뺄셈
- `S1-07`: 받아올림 없는 한 자리 3행

### MVP 2차

- `S2-02`: 받아올림 있는 +9
- `S2-03`: 받아올림 있는 +8
- `S2-04`: 받아올림 있는 +7
- `S2-05`: 받아올림 있는 +6
- `S2-06`: 받아올림 있는 +5
- `S2-07`: 받아올림 덧셈 혼합
- `S3-01`: 5를 활용한 덧셈
- `S3-02`: 10을 활용한 덧셈
- `S3-03`: 받아올림 있는 덧셈·뺄셈 3행

### 추후 구현

- `S4-01` 이후 50/100 만들기
- 두 자리 수 연속 계산
- 세 자리 수 계산
- 곱셈/나눗셈
- 암산 전환
- 속도 훈련
- 급수형 문제

## 8. 보상/게임 연동 메모

- 낮은 단계는 보상 배율을 낮게 둔다.
- 보수 단계부터 보상 배율을 올릴 수 있다.
- 3행/4행 문제는 문제당 피로도와 보상을 다르게 설정할 수 있다.
- stage 완료 횟수를 저장하면 나중에 자동 추천에 사용할 수 있다.
- stage별 성공률, 평균 풀이 시간, 오답 횟수를 저장하면 부모 리포트로 확장할 수 있다.
- 지금은 자동 추천/부모 리포트는 구현하지 않는다.
- 현재 게임 루프에서는 훈련 보상은 active dinosaur 성장과 코인 획득 중심으로 둔다.
- 알 부화 게이지는 훈련 직접 보상이 아니라 부화 아이템 사용으로 증가한다.

## 9. 이번 단계에서 하지 않는 것

- 실제 문제 생성기 전체 구현
- 고급 보수 문제 완성
- 급수 시험 모드
- 곱셈/나눗셈
- 디자인 리팩터링
- Bluetooth 로직 수정
