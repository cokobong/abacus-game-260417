# 공룡 주산 게임 오디오 설계

> 문서 상태: 1차 오디오 제작 명세  
> 권장 프로젝트 경로: `docs/audio-design.md`  
> 적용 대상: 훈련장, 결과 화면, 우리 공룡, 알부화장, 도감, 상점, 공통 UI

## 1. 목적

이 게임의 오디오는 단순히 버튼마다 소리를 붙이는 장식이 아니라, 아이가 화면을 계속 보지 않아도 다음 상태를 이해하게 만드는 피드백이다.

핵심 목표는 다음과 같다.

- 버튼 입력과 선택 성공 여부를 즉시 알려준다.
- 정답, 세트 완료, 레벨 상승, 부화처럼 중요한 보상을 분명하게 구분한다.
- 공룡이 먹이와 아이템에 반응해 살아 있는 캐릭터처럼 느껴지게 한다.
- 반복 학습 중 소리가 피로하거나 산만하지 않게 한다.
- 24종 공룡 전체를 처음부터 개별 녹음하지 않고도 충분한 다양성을 만든다.

## 2. 현재 게임 시스템 기준 오디오가 필요한 지점

현재까지 확정된 게임 구조를 기준으로 오디오 이벤트를 정리하면 다음과 같다.

| 화면/시스템 | 주요 행동 및 상태 |
| --- | --- |
| 공통 UI | 일반 버튼, 뒤로가기, 탭 전환, 좌우 선택, 비활성 버튼 |
| 훈련장 | 훈련 시작, 숫자 입력, 지우기, 답 제출, 정답, 오답, 다음 문제, 세트 완료 |
| 결과 화면 | 결과 등장, 경험치 획득, 코인 획득, 좋은 성적, 재도전 |
| 우리 공룡 | 공룡 전환, 먹이 선택, 먹이주기, 좋아하는 먹이, 배부름/사용 불가, 레벨 상승, 성장 단계 변화 |
| 알부화장 | 알 선택, 부화 아이템 선택·사용, 진행도 상승, 알 흔들림, 금이 감, 부화 가능, 부화 완료 |
| 도감 | 카테고리 전환, 카드 선택, 미발견 카드, 새 공룡 등록 |
| 상점 | 카테고리 전환, 상품 선택, 구매 성공, 코인 부족, 이미 보유/구매 불가 |
| 설정 | 효과음 켜기/끄기, 효과음 크기 조절, 추후 배경음 크기 조절 |

## 3. 오디오 전체 방향

### 분위기

- 밝고 선명한 어린이용 캐주얼 게임 사운드
- 나무, 방울, 마림바, 짧은 신시사이저, 부드러운 팝 계열
- 공룡 소리는 실제 맹수의 포효보다 장난감 캐릭터의 짧은 감탄에 가깝게 제작
- 실패음은 벌을 주는 느낌보다 “한 번 더 해보자”는 부드러운 안내로 제작

### 피해야 할 소리

- 갑자기 큰 저음 포효
- 날카로운 경고음과 사이렌 계열
- 오답 때 길고 우울한 하강음
- 버튼을 누를 때마다 0.3초 이상 이어지는 긴 소리
- 보상마다 같은 팡파르를 반복해 중요도가 구분되지 않는 구성
- 실제 동물 울음소리를 그대로 사용해 무섭거나 사실적으로 들리는 구성

## 4. 1차 제작 권장 수량

초기에는 **필수 26개**를 먼저 제작한다. 이 정도면 현재 게임의 모든 주요 행동을 덮을 수 있다.

이후 게임 화면에서 실제 반복 피로도를 확인한 뒤 권장 12개를 추가한다. 24종 공룡별 개별 울음소리는 마지막 확장 단계로 미룬다.

### 우선순위 정의

| 우선순위 | 의미 |
| --- | --- |
| P0 | 첫 오디오 적용 때 반드시 필요 |
| P1 | 기본 플레이가 안정된 뒤 추가하면 체감이 큰 소리 |
| P2 | 공룡별 개성, 모험, 이벤트 등 후속 확장 |

### 5.2 훈련장 7개

| ID / 파일명 | 사용 상황 | 길이 권장 | 제작 방향 |
| --- | --- | ---: | --- |
| `training_start_01` | 훈련 세트 시작 | 0.5~0.9초 | 짧은 준비 신호, 긴장감보다 기대감 |
| `training_number_input_01` | 화면 숫자 키패드 입력 | 0.04~0.08초 | 매우 작은 구슬/목재 틱 |
| `training_clear_01` | 입력값 지우기 | 0.08~0.15초 | 작게 쓸어내는 소리 |
| `training_submit_01` | 답 제출 | 0.10~0.18초 | 짧은 확인음 |
| `training_correct_01` | 정답 | 0.35~0.6초 | 밝은 2~3음 상승, 지나치게 크지 않음 |
| `training_wrong_retry_01` | 오답 | 0.25~0.45초 | 부드러운 짧은 하강 후 여운 없이 종료 |
| `training_set_complete_01` | 한 세트 완료 | 0.9~1.5초 | 정답음보다 한 단계 큰 미니 팡파르 |

숫자 입력음은 반복 횟수가 많으므로 다른 효과음의 약 25~35% 볼륨으로 둔다. nRF52840 주산기에서 들어오는 숫자 입력에도 적용할지는 실제 테스트 후 결정한다. 물리 구슬 소리와 겹쳐 산만하면 BLE 입력에는 재생하지 않는다.

## 7. 공룡 소리 확장 방식

### 1차: 공용 리액션 + 성장 단계 보정

처음부터 `24종 × 감정 × 3성장 단계`를 만들면 제작량과 관리 비용이 너무 커진다. P0에서는 공용 리액션을 사용하고 성장 단계에 따라 재생 특성만 조금 바꾼다.

| 성장 단계 | 권장 재생 보정 |
| --- | --- |
| 아기, 레벨 1~7 | 재생속도/음높이 약 `+6~10%`, 가볍고 짧게 |
| 청년, 레벨 8~19 | 원본 기준 |
| 성년, 레벨 20 이상 | 재생속도/음높이 약 `-4~7%`, 저음은 과하지 않게 |

브라우저 구현에서 `playbackRate`만 사용하면 길이도 함께 변하므로 차이를 작게 유지한다.

### 2차: 체형별 4개 보이스 그룹

P1 또는 P2에서 24종을 아래 그룹으로 나누면 적은 파일로도 개성이 생긴다.

| 그룹 | 예시 공룡 | 소리 성격 |
| --- | --- | --- |
| 대형 육식 | 티라노, 알로, 스피노, 카르노 | 낮지만 둥근 짧은 포효 |
| 소형 민첩 | 벨로키랍토르, 데이노니쿠스, 오비랍토르, 갈리미무스 | 빠른 삑/찍/짧은 재잘거림 |
| 대형 초식·긴 목 | 브라키오, 디플로도쿠스, 아마르가사우루스 | 부드러운 관악기 같은 낮은 울림 |
| 뿔·갑옷 초식 | 트리케라톱스, 스테고, 안킬로, 켄트로 등 | 코웃음과 둥근 훔 소리 |

### 3차: 대표 공룡만 고유 시그니처

플레이 테스트 후 아이가 특히 자주 사용하는 대표 4종부터 고유 소리를 추가한다.

- 티라노사우루스
- 브라키오사우루스
- 트리케라톱스
- 스테고사우루스

각 공룡마다 모든 감정을 만들 필요는 없다. `등장/선택`, `기쁨`, `좋아하는 먹이` 3개만 먼저 만들어도 충분히 개성이 느껴진다.

## 8. 화면별 재생 규칙

### 공통 UI

- 실제 상태 변화가 없는 장식 터치에는 소리를 내지 않는다.
- 버튼 클릭음과 해당 결과음이 연속될 때는 클릭음을 작게 하거나 생략한다.
- 같은 소리가 80ms 이내에 반복 호출되면 두 번째 재생을 막는다.
- 비활성 버튼은 `ui_blocked_01`만 한 번 재생하고 다른 결과음은 재생하지 않는다.

### 훈련장

- 정답: 제출음 뒤 `training_correct_01`
- 오답: 제출음 뒤 `training_wrong_retry_01`
- 오답 후 정답으로 바뀐 경우 정답음을 재생하되 기존 오답음과 겹치지 않게 한다.
- 자동 다음 문제 전환에는 별도 효과음을 추가하지 않는다.
- 문제를 8개 숫자로 설정해도 입력음이 누적되어 시끄럽지 않아야 한다.
- 세트 마지막 정답에서는 정답음을 생략하거나 짧게 재생한 뒤 `training_set_complete_01`로 자연스럽게 연결한다.

### 결과 화면

권장 순서:

```text
결과 패널 등장
→ 경험치 증가
→ 코인 증가
→ 레벨 상승이 있다면 레벨 상승음
→ 성장 단계 변화가 있다면 성장 변화음
```

한 번에 여러 팡파르가 겹치지 않게 앞 소리를 페이드아웃하거나 다음 소리를 늦춘다.

### 우리 공룡

권장 먹이주기 순서:

```text
먹이 선택음
→ 먹이주기 버튼
→ 아이템 차감 성공
→ 먹는 소리
→ 일반 또는 좋아하는 먹이 리액션
```

- 재고가 없거나 사용할 수 없으면 먹는 소리를 재생하지 않는다.
- 좋아하는 먹이는 `dino_eat_01` 뒤 `dino_favorite_food_01`을 재생한다.
- 공룡 좌우 전환 때마다 울음소리를 내면 피로하므로 `ui_switch_01`만 기본 재생한다.
- 같은 공룡을 잠시 바라보고 있거나 처음 선택했을 때만 낮은 확률의 공룡 리액션을 추후 고려한다.

### 알부화장

- 단순 알 선택: `ui_switch_01`
- 아이템 선택: `ui_select_item_01`
- 사용 성공: `hatch_item_use_01`
- 진행도 증가: `hatch_progress_gain_01`
- 25~50%: 기본 진행음, 필요하면 P1의 작은 흔들림음 추가
- 75~90%: `hatch_egg_crack_01`
- 100% 도달: 바로 공룡을 공개하지 않고 “부화하기” 버튼까지 기다린다면 준비 상태에는 짧은 반짝임만 재생
- 사용자가 부화하기를 누른 순간 `hatch_reveal_01`

### 도감과 상점

- 도감 카드 선택은 공통 선택음 재사용
- 새 공룡을 처음 등록할 때만 `pokedex_unlock_01`
- 이미 등록된 공룡을 다시 열 때 해금음을 반복하지 않는다.
- 구매 성공 시 코인 차감음과 구매 성공음을 겹치지 않는다.
- 코인 부족은 낮고 짧게 끝내며 아이가 혼난다는 느낌을 주지 않는다.

## 9. 믹싱과 파일 기술 규격

### 권장 원본

- 원본 마스터: WAV, 48kHz, 24-bit
- 게임 배포본: OGG 또는 WebM/Opus 우선, 호환용 MP3 선택 가능
- 아주 짧은 UI 효과음은 WAV 사용도 가능
- 모노 권장: 버튼, 숫자 입력, 공룡 보컬
- 스테레오 허용: 부화 공개, 성장 변화, 큰 보상 팡파르
- 시작과 끝의 불필요한 무음 제거
- 클릭 노이즈 방지를 위해 시작/끝에 매우 짧은 페이드 적용

### 체감 볼륨 기준

| 그룹 | 상대 볼륨 출발값 |
| --- | ---: |
| 숫자 입력 | 0.20~0.30 |
| 일반 UI | 0.35~0.45 |
| 정답/오답 | 0.50~0.60 |
| 먹이/공룡 반응 | 0.50~0.65 |
| 세트 완료/보상 | 0.65~0.75 |
| 성장/부화 공개 | 0.75~0.85 |

위 수치는 절대값이 아니라 구현 초기의 상대 기준이다. 개별 파일의 라우드니스를 먼저 비슷하게 정리한 뒤 조절한다.

### 동시 재생 제한

- 일반 UI 소리: 최대 2개
- 공룡 보컬: 한 번에 1개
- 팡파르/부화/성장: 한 번에 1개
- 새로운 중요 효과가 시작되면 이전 중요 효과를 50~120ms에 걸쳐 페이드아웃
- 숫자 입력음은 빠른 연속 입력 시 이전 소리를 중단하고 새 소리를 재생해 소리가 쌓이지 않게 함

## 10. 파일과 코드 구조 권장안

```text
src/assets/audio/
├─ ui/
├─ training/
├─ reward/
├─ dino/
├─ hatch/
├─ shop/
└─ pokedex/
```

파일명에는 공백, 한글, 대문자를 사용하지 않는다.

```text
<system>_<event>_<variant>.<ext>

ui_tap_soft_01.ogg
training_correct_01.ogg
dino_favorite_food_01.ogg
hatch_reveal_01.ogg
```

오디오 경로는 컴포넌트마다 직접 import하지 않고 중앙 매핑에서 관리한다.

```ts
export const AUDIO_IDS = {
  uiTapSoft: 'ui_tap_soft_01',
  trainingCorrect: 'training_correct_01',
  dinoFavoriteFood: 'dino_favorite_food_01',
  hatchReveal: 'hatch_reveal_01',
} as const
```

재생 함수는 최소한 아래 기능을 제공해야 한다.

- 효과음 전체 켜기/끄기
- 효과음 전체 볼륨
- 카테고리별 기본 볼륨
- 같은 효과음의 과도한 중복 방지
- 중요한 효과음이 겹치지 않도록 그룹 제어
- 모바일 브라우저의 첫 사용자 입력 이후 오디오 활성화
- 존재하지 않는 오디오 파일 때문에 게임이 중단되지 않는 안전 처리

## 11. 설정 및 접근성

- 기본값은 효과음 켜짐
- 설정에서 효과음 끄기 제공
- 1차에는 `효과음 켜기/끄기`만 있어도 충분
- 배경음악을 추가할 때는 효과음과 별도 조절
- 오디오가 꺼져도 정답, 오답, 구매 실패, 부화 가능 상태를 화면 애니메이션과 색으로 알 수 있어야 함
- 소리를 끈 상태가 새로고침 후에도 유지되도록 로컬 저장

## 12. 제작 순서

### 1단계: 반복 플레이 핵심

1. 공통 UI 6개
2. 훈련장 7개
3. 결과·보상 5개

이 단계에서 실제 문제 20개 세트를 플레이해 반복 피로도를 먼저 확인한다.

### 2단계: 육성 재미

1. 공룡 리액션 4개
2. 알부화장 4개
3. 먹이주기와 레벨·성장 연출의 타이밍 조정

### 3단계: 구분감 강화

1. P1 권장 12개 중 실제 구현된 기능만 추가
2. 대표 4종 고유 공룡 소리 테스트
3. 필요하면 체형별 보이스 그룹 확장

## 13. 실제 코드 저장소에서 추가 확인할 항목

현재 문서는 확정된 게임 기획과 화면 흐름을 기준으로 작성했다. 실제 오디오 코드 적용 전에는 저장소에서 다음을 확인해야 한다.

- 버튼 공통 컴포넌트가 존재하는지
- 하단 내비게이션과 각 화면 탭이 같은 클릭 컴포넌트를 쓰는지
- 훈련 정답/오답 판정이 발생하는 정확한 함수
- BLE 자동 제출과 화면 키패드 제출이 같은 로직을 거치는지
- 세트 완료와 결과 화면 진입이 분리된 이벤트인지
- 경험치, 코인, 레벨 상승, 성장 단계 변화가 각각 구분 가능한 상태값인지
- 먹이 아이템 차감 성공 이후에만 리액션을 실행할 수 있는지
- 좋아하는 먹이 데이터가 현재 24종 데이터에 실제 연결되어 있는지
- 부화 진행도 25/50/75/90/100% 이벤트가 존재하는지
- 부화 아이템이 즉시 적용인지 다음 훈련 세트 보너스인지
- 구매 실패 사유를 코인 부족과 조건 불충족으로 구분할 수 있는지
- 기존 오디오 라이브러리 또는 사운드 설정 코드가 있는지

좋아하는 먹이, 배고픔, 연속 정답, 최고 기록처럼 아직 코드에 없는 기능은 오디오를 먼저 연결하기 위해 새 게임 기능으로 만들지 않는다.

## 14. 1차 완료 기준

- P0 26개 파일이 정해진 이름과 폴더에 존재한다.
- 일반 버튼을 빠르게 눌러도 소리가 과도하게 겹치지 않는다.
- 숫자 8개 문제와 20문제 세트를 끝까지 풀어도 입력음이 피로하지 않다.
- 정답, 오답, 세트 완료가 화면을 보지 않아도 구분된다.
- 경험치, 레벨 상승, 성장 단계 변화가 서로 다른 보상으로 들린다.
- 아이템이 실제로 차감된 경우에만 먹는 소리와 공룡 반응이 난다.
- 부화 진행과 최종 공룡 공개가 명확히 구분된다.
- 레벨 1, 8, 20 공룡의 리액션 음색 차이가 과하지 않으면서 구분된다.
- 음소거 상태에서도 게임 진행과 피드백이 정상이다.
- iPad Safari와 데스크톱 브라우저에서 첫 입력 이후 안정적으로 재생된다.
- 오디오 파일 로딩 실패가 게임 전체 오류로 이어지지 않는다.

## 15. 최종 권장 결론

첫 제작은 **P0 26개**로 제한한다. 그중에서도 가장 먼저 확인할 것은 훈련장 7개다. 이 게임은 학습 반복 시간이 가장 길기 때문에, 훈련 소리가 편안해야 나머지 화려한 부화·공룡 소리도 의미가 있다.

공룡은 처음부터 24종별 소리를 만들지 않는다. 공용 리액션 4개와 성장 단계별 작은 음높이 차이로 시작한 뒤, 실제로 자주 쓰는 대표 4종에만 고유 시그니처를 추가하는 순서가 제작 효율과 게임 완성도 모두에 유리하다.
