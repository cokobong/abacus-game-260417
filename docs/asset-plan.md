# 에셋 관리 계획

이 문서는 이미지와 아이콘 같은 시각 에셋을 어떻게 관리할지 정리한다.

## 1. 기본 원칙

- 이미지는 코드 안에 직접 넣지 않는다.
- 이미지 파일은 `assets` 계열 폴더에 따로 둔다.
- TypeScript 데이터 파일에서는 이미지 경로만 참조한다.
- 문서에는 에셋의 방향성과 필요한 종류를 정리하고, 실제 데이터는 구현 파일에서 관리한다.

## 2. 필요한 에셋 종류

초기 버전에 필요한 에셋 후보:

- 알 이미지
- 기본 캐릭터 이미지
- 캐릭터 진화형 또는 성장 단계 이미지
- 먹이 아이콘
- 장난감 아이콘
- 코인 아이콘
- 희귀 알 조각 아이콘
- 탭 아이콘
- 모험 지역 배경 또는 썸네일

## 3. 탭별 에셋 방향

### 부화방

- 알 상태가 한눈에 보여야 한다.
- 부화 게이지, 반짝임, 균열 등 성장 상태를 표현할 수 있다.

### 놀이터

- 캐릭터 표정과 반응이 중요하다.
- 장난감이나 먹이 아이콘은 단순하고 귀엽게 만든다.

### 도감

- 발견 전 실루엣 이미지가 필요하다.
- 발견 후에는 캐릭터가 명확하게 보이는 정면 또는 3/4 뷰가 좋다.

### 모험

- 숲길, 연못, 구름섬, 장난감 마을처럼 지역 분위기를 작은 썸네일로 구분한다.
- 보상 아이콘은 작게 보아도 구분되어야 한다.

### 상점

- 아이템 이미지는 카드 안에서 가격, 이름과 함께 보여야 한다.
- 초기에는 먹이와 장난감 중심으로 적은 수만 준비한다.

## 4. 데이터와 이미지 연결

추후 구현에서는 다음과 같은 방향을 따른다.

```text
src/data/items.ts
→ 아이템 이름, 카테고리, 가격, 효과, 이미지 경로 관리

assets/
→ 실제 이미지 파일 관리
```

문서에는 “어떤 종류의 아이템과 이미지가 필요한지”만 정리하고, 실제 게임 데이터는 TypeScript 파일에서 관리한다.
