# 심해협곡 아케이드 재설계 최종 기획

## 문서 지위와 한 문장 정의

**이 문서는 심해협곡의 최우선 기획 기준이다.** [기존 전체 기획](./deep-sea-game-design.md), [Stage 2 레벨 설계](./deep-sea-stage2-level-design.md), [Stage 2 구현 계획](./deep-sea-stage2-implementation-plan.md), [Phaser 계획](./deep-sea-phaser-plan.md), [목업 계획](./deep-sea-mockup-plan.md)은 삭제하지 않고 과거 탐험형 설계의 참고자료로 둔다. 규칙·수치·용어가 충돌하면 이 문서를 우선한다. 이 문서는 **구현 목표**이며, 아래 코드 조사에서 별도로 표시한 현행 동작을 이미 구현된 기능으로 해석하지 않는다.

> **심해협곡은 짧은 시간 안에 한 판이 자연스럽게 끝나는, 적을 피하거나 파워업으로 역습하며 바닷속 보물을 모아 탈출하는 잠수함 아케이드 미니게임이다.**

Stage별 1~2분 / 2~3분 / 3~4분은 목표 플레이타임이며 강제 countdown timer나 시간 초과 실패 조건은 기본 규칙에 없다.

주산 훈련 → 코인 획득 → 입장료를 내고 한 판 → 코인·아이템·바닷속 보물 획득 → 결과 화면 → 다시 모험 또는 훈련장으로 돌아간다. 즉각적인 이동과 활발한 적이 한 판의 재미를 만들고, **바닷속 보물도감**은 반복 플레이의 이유이며, **Stage 3 클리어 뒤 유물조각**은 장기 보상이다. 훈련장이 코인의 기본 공급원이고 심해협곡만 반복해 코인이 순증해서는 안 된다.

## 한 판의 규칙

| 항목 | 확정 설계 기준 |
| --- | --- |
| Stage | Stage당 한 판. Mission 1/2/3 분할 없음. 클리어·3회 피격 실패·중단 후 결과/복귀로 종료. |
| 조작 | 화면 4방향 패드와 키보드 보조 입력. 타일 중심에서 방향을 바꾸며, 교차로 직전 입력은 예약한다. 빠른 반응과 즉시 반대 방향 전환을 우선한다. |
| 클리어 | 판마다 지정된 **목표 보물 3개**를 획득하면 출구가 활성화된다. 출구에 닿으면 클리어. 모든 코인 수집은 요구하지 않는다. |
| 선택 수집 | 통로 코인, 일반 상자, 도감용 바닷속 보물 1~3개. 선택 수집은 출구 조건을 늘리지 않는다. |
| 위험 | 상어·문어가 중심이고 Stage에 따라 해파리·복어를 더한다. 잠수함이 멈춰도 적과 환경은 계속 움직인다. |
| 역전 | **전기 구슬**을 먹으면 6~8초 동안 적이 도망가고 접촉한 적은 잠시 기절/퇴장한다. 추가 코인은 한 판 정산 상한 안에 든다. |
| 피격 | 내부 생명력 3. 첫 피격은 `damaged`, 둘째는 `critical`, 셋째는 실패. 하트 HUD는 사용하지 않고 잠수함 외형과 짧은 피드백으로 알린다. |
| 시간 | 아래 시간은 아이 테스트의 **목표 중앙값**이지 즉시 실패하는 제한시간이 아니다. 오래 헤맬 때 목표·출구 방향 도움을 강화해 판이 장시간 탐험으로 바뀌지 않게 한다. |

목표 보물은 해당 판의 출구 열기용으로 생성한 세 물체다. 도감용 보물은 별도 선택 수집 풀에서 나온다. 같은 이미지나 위치를 공유하더라도 HUD의 `목표 보물 0/3`과 도감의 신규 발견 표시는 분리해야 한다. 시작 시 출구는 잠겨 있고, 세 번째 목표 획득 직후 출구 빛·문 열림·HUD 안내를 동시에 보여준다. 활성화 뒤에는 마지막 목표에서 출구까지 짧은 경로가 남아야 하며 긴 귀환을 강제하지 않는다.

### Stage별 구성

| Stage | 한 판 목표 | 권장 타일 범위 | 적·전기 구슬·환경 | 보물 풀과 보상 |
| --- | --- | --- | --- | --- |
| 1: 침몰선 초입 | 약 **1~2분**. 이동·목표·출구·역전 학습 | **16×16~18×18** | 적 1~2마리, 전기 구슬 0~1개, 환경기믹 거의 없음 | 흔한 도감 보물 중심 5~6종. 낮은 입장료 |
| 2: 바닷속 옛 도시 | 약 **2~3분**. 교차로 선택과 추격 회피 | **20×20~24×24** | 적 약 3마리, 전기 구슬 1~2개, 암벽문 또는 해류 | 보물 6~8종, 귀한 보물 등장. 중간 입장료 |
| 3: 깊은 바다 신전 | 약 **3~4분**. 세 시스템의 종합 | **22×22~26×26** | 적 약 4마리, 전기 구슬 1~2개, 환경기믹 1~2종 | 보물 8~10종, 아주 귀한 보물. 클리어 결과에서 유물조각 추첨 |

타일 수는 출발점이다. 테스트에서 난이도를 좌우할 것은 교차로·루프·적·수집물 밀도와 안전한 회피 경로다. 크기나 긴 복도를 늘려 시간을 채우지 않는다. 초반 Stage 1 한 판은 적이 있어도 안전한 관찰 공간을 확보한다. Stage 2와 3도 적의 수만 늘리지 말고 서로 다른 이동 패턴을 조합한다.

## 통로 맵·카메라·조작

맵은 좁은 통로, 십자·T자 교차로, 사각 루프, U자 우회로, 짧은 막다른 길, 작은 방, 보물방, 전기 구슬방, 위험 통로, 출구 구역의 **검증된 템플릿 조합**으로 매판 만든다. 완전한 무작위 벽 생성은 우선하지 않는다. 시작점·목표 세 곳·출구·선택 보물·적 스폰의 역할을 배치하고, 같은 보드 반복을 줄일 만큼 템플릿 연결과 장식·보상 위치를 바꾼다. 생성 실패 시 검증된 예비 보드로 대체한다.

생성 직후 통행 그래프를 검사한다. 시작점에서 목표 3개와 출구가 닿아야 하고, 고립된 바닥 구역이 없어야 한다. 출구는 목표 획득 뒤 도달 가능해야 한다. 동적 문이 닫힌 상태에서도 필수 구역에 대체 경로나 복구 동작이 있어야 한다. 적은 플레이어 시작점 바로 옆이나 피할 수 없는 좁은 통로에 스폰하지 않는다. 목표 3개를 모은 뒤 출구까지의 최단 타일 거리를 제한해 긴 되돌아가기를 막는다. 검증에는 생성 seed와 실패 사유를 남겨 재현한다.

카메라는 잠수함을 부드럽게 따라가되 월드 경계에서 멈춘다. 세로 iPad 화면에서 맵 전체를 축소해 보여주지 않고, **맵 면적의 약 35~50%**가 보이도록 Stage·기기별 zoom을 조정한다. 잠수함·적·코인이 손가락 조작 중에도 식별될 크기를 우선하며 과도한 확대와 늦은 추적을 피한다. HUD와 패드는 화면에 고정하고, 진행 방향 앞쪽을 조금 더 보이게 할 수 있다. 교차로에서 누른 다음 방향은 타일 중심 도착 시 유효하면 실행하고, 막혔으면 현재 이동을 유지한다. 포인터 취소·화면 이탈 시 눌린 방향을 해제한다.

미니맵은 현재 위치, 기본 통로, 지나간 영역, 출구, **발견한** 목표 위치만 표시한다. 적 위치는 기본적으로 보이지 않는다. 예전의 복잡한 미탐험 안개, 상세 구역 탐색률, 장시간 공간기억 체계는 사용하지 않는다. 이전 소나는 기본 능력으로 두지 않는다. 소나 자산·효과는 전기 구슬의 짧은 탐지 연출 등에 제한적으로 재검토할 수 있으나, 파워업의 핵심은 **추격 관계 역전**이다.

## 적 AI·전기 구슬·파손

적은 통행 그래프를 따라 계속 움직인다. 기본 상태는 `PATROL → CHASE → RETURN`이며 전기 구슬 동안 `FLEE`, 붙잡히면 `STUNNED/RESPAWN`이 끼어든다. 화면 밖에서도 세계 시간이 멈추지는 않지만 멀리 있는 적은 저주기 위치 갱신이나 순찰점 계산으로 비용을 낮춘다. 벽을 가로지르는 직선 추적은 금지한다. 전기 구슬이 끝나면 적은 자기 구역으로 돌아와 다시 순찰한다.

| 적 | 행동·읽을 수 있는 단서 | 초기 속도 비율(잠수함 1.0) |
| --- | --- | --- |
| 상어 | 적극적 추격. 가까워지면 통로를 따라 따라오고 멀어지면 순찰 구역으로 복귀. 추격 시작을 방향·표정으로 알림 | 순찰 **0.85~0.95**, 추격 **1.0~1.05** |
| 문어 | 다음 교차로를 막는 성향. 짧은 예측 차단 후 복귀하며 상어보다 추격 반경이 짧음 | **0.7~0.8** |
| 해파리 | 느린 왕복으로 움직이는 벽. 경로와 방향을 쉽게 예측 가능 | **0.4~0.5** |
| 복어 | 통로 왕복. 가까워지면 예고 뒤 잠시 팽창해 길을 막는 후보 | Stage 2/3 아이 테스트로 결정 |

아이용 AI는 최적 경로로 반드시 잡는 능력이 아니라 **예고·우회·회복 가능성**을 제공해야 한다. 적과 플레이어가 같은 좁은 통로에 생성되어 피할 틈이 없는 배치는 검증에서 거른다. 기본 속도는 출발값이고 실제 iPad 플레이로 튜닝한다.

전기 구슬은 아이 화면에서 쉬운 이름을 쓴다. 획득 즉시 잠수함이 빛나고 적의 색·표정이 바뀌며 도망간다. 지속시간은 **6~8초**. 강화 중 접촉한 적은 잠시 화면에서 빠졌다가 자기 스폰 근처에서 예고 후 복귀한다. 적이 영구 제거되지 않고, 추가 코인은 입장료보다 낮은 한 판 보상 상한에 포함된다. 끝나기 직전 시각·소리로 경고한다. 전기 구슬이 없는 Stage 1 판도 있을 수 있으므로 첫 사용법은 별도 짧은 안내나 첫 스폰 배치로 학습시킨다.

잠수함 상태는 `health=3 → normal`, `2 → damaged`, `1 → critical`, `0 → failure`로 매핑한다. Scene의 health를 단일 진실 값으로 쓰고 피격·회복·재도전에서 외형을 동기화한다. 기존 약 **1.3초** 무적시간과 짧은 점멸은 재사용할 수 있다. 별도 하트 HUD와 하트 소진 문구는 교체한다. 수리 아이템을 다시 켤 경우 회복이 게임 시간을 늘리거나 세 번째 피격 규칙을 흐리지 않게 별도 아이 테스트 후 정한다. 첫 아케이드 버전에서는 수리 픽업을 제외하는 안을 권장한다.

환경기믹은 Stage당 1~2종만 쓴다. 암벽문은 열리고 닫히는 주기와 닫히기 전 예고가 있어야 하고, 잠수함·적이 문에 끼이면 안전하게 밀어내거나 닫힘을 늦춘다. 해류는 방향 이동을 돕거나 잠깐 빠르게 만들되 조작권을 빼앗지 않는다. 열수 분출구는 통로 예고형 장애물, 문어 촉수는 Stage 3 후보로 둔다. 적 AI보다 기믹 설명이 복잡해지면 제외한다.

## 코인·바닷속 보물·도감

코인은 통로에 일정 간격으로 놓아 길을 보여주고 수집 손맛을 준다. **선택 보상**이며 전부 먹어야 출구가 열리지는 않는다. 획득 코인, 적을 기절시킨 보너스, 중복 보물 보너스를 합산해 **한 판 지갑 정산 상한**을 적용한다. HUD의 코인은 판에서 모은 수를 보여주고, 실제 지갑은 결과 정산 시 한 번만 바꾼다.

아이에게는 **바닷속 보물**, **바닷속 보물도감**이라고 표시한다. 내부 코드에 `artifact`를 유지하더라도 화면에는 아티팩트·인장·석판·성물 같은 전문용어를 쓰지 않는다. 이름은 물체가 떠오르는 쉬운 말로 정하고 별 등급은 `★ 흔한 보물 / ★★ 귀한 보물 / ★★★ 아주 귀한 보물`로 표현한다.

| Stage | 도감용 보물 풀 초안 |
| --- | --- |
| 1: 5~6종 | 오래된 나침반, 녹슨 배 열쇠, 조개 목걸이, 금빛 동전, 병 속의 지도, 작은 선장 장식 |
| 2: 6~8종 | 그림이 새겨진 돌판, 금빛 항아리, 부서진 왕관, 물고기 그림 접시, 눈이 빛나는 돌상, 별 모양 금속 조각, 파란 보석 상자, 커다란 옛날 종 |
| 3: 8~10종 | 빛나는 세 갈래 창, 푸른 수정, 황금 물고기상, 해마 모양 왕관, 빛나는 진주, 별빛 보석, 바다왕의 금 열쇠, 커다란 파란 눈 보석, 황금 소라, 빛나는 조개 왕관 |

이름과 최종 이미지는 도감 제작 때 다시 검수한다. 한 판에 도감용 보물은 풀에서 **1~3개**가 발견 가능하도록 스폰한다. 희귀 보물은 낮은 확률로 나오며, 맵 seed·보물 추첨·획득 기록은 런별로 고정해 재시작이나 중복 콜백으로 다시 뽑히지 않게 한다. 도감 항목에는 이미지, 쉬운 이름, 획득 여부, 발견 Stage, 별 등급, 한 문장 설명을 둔다. 미획득 항목은 실루엣·`???`·발견 가능한 Stage만 보여준다. 공룡도감의 `discoveredSpeciesIds`와 섞지 않고 독립 저장한다.

**중복 보물 처리 비교**

| 안 | 장점 | 부담 |
| --- | --- | --- |
| A. 도감 변화 없음 | 가장 단순하고 코인 경제 영향 없음 | 중복 발견의 손맛이 약함 |
| B. 소량 코인 지급 | 다시 발견해도 즉시 보상이 있음 | 코인 정산 상한·실패 정책과 함께 관리해야 함 |
| C. 발견 횟수 기록 | 수집 기록을 쌓는 동기 | 도감 UI와 저장 데이터가 복잡해짐 |

**추천: B.** 중복은 새 도감 항목으로 세지 않고, 별 등급에 따라 소량 코인을 한 판 보상에 더하되 정산 상한 안에 넣는다. 별도 조각 화폐는 만들지 않는다. 정확한 코인 수와 희귀도 확률은 경제 시뮬레이션·아이 테스트에서 확정한다.

## 입장료·실패·결과 정산

다음 숫자는 **새 제안값**이다. 현행 심해 입장료 0과 다르며, 구현 전에 실제 훈련 코인 획득량 및 플레이 테스트로 확정해야 한다.

| Stage | 일반 입장료 제안 | 지갑 코인 정산 상한 제안 | 목표 평균 회수(클리어 판) |
| --- | ---: | ---: | ---: |
| 1 | 60코인. 첫 입문판 1회 무료 가능 | 30코인 | 10~20코인 |
| 2 | 90코인 | 45코인 | 20~30코인 |
| 3 | 120코인 | 60코인 | 30~45코인 |

상한 자체도 입장료보다 낮게 잡아 코인만으로는 무한 순증할 수 없게 한다. **첫 무료 입문권은 계정당 한 번**이어야 한다. 재도전 입장료와 아이템 환금 가능성도 같은 경제 시뮬레이션에서 검사한다. 훈련장은 코인 공급원, 모험은 선택 소비 콘텐츠라는 관계를 유지한다. 보물도감·유물조각은 코인과 별개 영구 기록이다.

실패는 세 번째 피격 즉시 발생하며 `다시 도전 / 모험맵으로`를 보여준다. 입장료는 반환하지 않는다.

| 실패 시 보상안 | 장단점 |
| --- | --- |
| 전부 잃음 | 단순하지만 어린이가 찾은 보물까지 사라져 좌절이 큼 |
| 새 도감 기록만 유지 | 탐색 노력은 남고 코인·아이템·유물조각 파밍은 막음 |
| 코인·아이템 일부 유지 | 위로는 되지만 반복 실패가 경제 루프를 흐릴 수 있음 |

**추천: 새로 찾은 도감 항목은 유지하고, 지갑 코인·아이템·유물조각은 실패/중단 시 지급하지 않는다.** 이미 보유한 항목의 중복 코인 보너스도 클리어 시에만 정산한다. 이를 위해 런 중 코인은 `pending`으로 들고 있다가 결과 한 번만 커밋한다. 도감의 신규 획득은 런 내 `treasureId` 중복을 제거해 별도 저장한다. 실패를 반복해 희귀 도감만 빠르게 모으는 행동이 나타나면 희귀 스폰 확률·입장료를 조정한다.

결과 화면은 클리어/실패, 획득 코인, 새 바닷속 보물, 아이템을 간결히 표시한다. 새 보물을 얻었다면 “새 보물을 찾았어요!”를 강조하고 도감으로 갈 수 있게 한다. Stage 3 **클리어** 결과에는 유물조각 획득 여부와 현재 `n/5`를 추가한다. 지급·Stage 완료·도감 업데이트는 같은 `runId`에서 한 번만 실행한다.

## Stage 3 유물조각과 최종 유물

**바닷속 보물과 최종 유물조각은 서로 다른 저장·보상 시스템이다.** 전자는 판 중 발견하고 도감을 채운다. 후자는 Stage 3 출구로 끝까지 클리어했을 때 결과/보물상자에서만 추첨한다. 판 중에 유물조각을 스폰하지 않는다. 실패·중단·Stage 1/2 클리어에는 조각 추첨이 없다.

기본 제안은 Stage 3 클리어당 **37.5%**, 이미 가진 부품은 후보에서 제외, **연속 2회 미획득 뒤 다음 클리어에서 확정**이다. 성공하면 연속 실패 횟수를 0으로 되돌린다. 5개를 모으면 기존 [심해협곡 지역 유물 정의](../src/config/regionalRelicConfig.ts)의 부품과 [유물 진행 저장](../src/config/worldMapRelicConfig.ts)을 재사용해 유물보관소에서 **심해왕의 진주 성배**를 복원한다. 다섯 부품 이미지와 완성 이미지가 이미 있다. 도감용 보물 `빛나는 진주` 등은 유물 부품 `abyss_pearl`과 별개 ID·별개 UI로 유지한다.

현행 공통 `resolveRegionFinalChest()`는 37.5% 기본, 2회 미획득 후 70%, **3회 미획득 후 다음 회차 확정**이다. 새 제안의 “2회 뒤 다음 확정”과 다르므로 심해협곡 전용 설정 또는 지역별 설정 인자로 분리해야 한다. 현행 `App.tsx`의 유물 지급 분기는 용암계곡·하늘섬에만 있고 심해협곡은 연결되지 않았다. 예전 문서의 `Final Map` 해금·완료 단계는 이번 짧은 아케이드 루프에서 **보류**하고, 5개 수집 → 유물보관소 복원을 기준으로 한다. 기존 저장 필드와 다른 지역 유물 진행은 변경하지 않는다.

## 현행 코드 조사: REUSE / EXTEND / REPLACE / REMOVE·DEFER

현행 Stage 1/2는 이미 플레이 가능한 **탐험형 목업**이다. 아래 분류는 설계 전환 시 작업 판단이며 이번 문서 작성으로 코드를 바꾸지 않는다.

| 영역 | 현재 코드 상태 | 판단과 변경 방향 |
| --- | --- | --- |
| 진입·생명주기 | [AdventureGameShell](../src/components/screens/AdventureGameShell.tsx)이 심해 Stage 1/2를 Host에 연결. Host가 Phaser를 지연 로딩·destroy | **REUSE**. Stage 3 연결은 최종 Phase에서 추가 |
| Phaser Scene | [createDeepSeaGame](../src/components/screens/deepSea/createDeepSeaGame.ts)의 단일 Scene에 이동·맵·적·발견·보상이 집중 | **EXTEND/REPLACE**. 상태·맵 생성·보상 규칙을 작은 순수 모듈로 분리 |
| 이동·벽 | 4방향 타일 중심 이동, `walls` 집합 판정. 버튼을 누르는 동안 `heldDirection`만 유지 | 타일·벽 판정 **REUSE**, 교차로 예약 입력·즉시 반전·문 상태 판정 **EXTEND** |
| 맵 생성 | [Stage 1](../src/config/deepSea/stage1.ts) 26×26 고정 벽, [Stage 2](../src/config/deepSea/stage2.ts) 36×36 사각 carve 고정 맵. 런별 seed·템플릿 없음 | **REPLACE** 맵 데이터. 템플릿 조합·접근성 검사·예비 보드 추가 |
| 카메라 | 잠수함 follow, bounds, lerp, deadzone, Stage별 zoom | **REUSE/EXTEND**. 세로 화면에서 면적 35~50%·잠수함 가독성 튜닝 |
| 시야·소나 | `renderFog()`가 Stage 2의 모든 타일을 다시 그림. 소나 3회로 일시 반경 확대 | 복잡한 fog **REMOVE/DEFER**, 간단한 미니맵 **NEW**. 소나 기본 규칙은 **DEFER** |
| 상어 AI | 가까우면 플레이어 좌표로 직선 이동, 벽 경로 검사 없음 | 순찰 데이터·비주얼 **REUSE**, PATROL/CHASE/RETURN·통로 경로·FLEE **REPLACE** |
| 문어 AI | 집 주변에서 직선 접근·복귀, 교차로 차단 없음 | 비주얼·home 데이터 **REUSE**, 예측 차단·복귀·FLEE **REPLACE** |
| 해파리·복어 | 현재 Stage 1/2 config와 Scene에 없음 | **NEW**. Stage별 밀도를 보며 단계적으로 추가 |
| 파워업 | 역전 상태·적 도주·기절·복귀 없음 | **NEW** 전기 구슬, 6~8초 상태 머신과 연출 |
| 체력·피격 | Scene `health=3`, 1.3초 무적, 셋째 피격 실패. Host에 하트 HUD | 내부 피해 규칙 **REUSE**, 3장 잠수함 외형 **EXTEND**, 하트 HUD **REPLACE** |
| 발견·목표 | `coral/statue/chest` 근접 자동 발견, Stage 1은 2개·Stage 2는 3개로 출구 개방 | 출구 잠금·콜백 **REUSE**, 목표 3개와 선택 도감 보물 구분 **REPLACE** |
| 코인·상자 | Stage 2에 코인 8개·작은 상자 2개·수리·소나 픽업. 코인은 클리어에만 지급 | 픽업·중복 방지 **REUSE**, 통로 밀도·아이템·정산 **EXTEND**. 수리·소나는 첫 버전 **DEFER** |
| 출구·결과 | 목표 후 출구 열림, 타일 도달 시 클리어. 실패/클리어 overlay와 재도전 버튼 | 상태 흐름 **REUSE**, 목표/도감/유물/코인 표시 **EXTEND** |
| Stage config | `DeepSeaMapConfig.stage`와 Host·factory는 `1 | 2`, Stage 3는 [catalog](../src/config/adventureStageCatalog.ts)에서 미구현 | Stage 1/2 연결 **REUSE**, 아케이드 데이터 **REPLACE**, Stage 3 연결은 Phase 8~10 |
| 입장료·코인 | [minigameConfig](../src/config/minigameConfig.ts)의 심해 입장료는 **0**. [App](../src/App.tsx)은 심해를 0원 분기로 진입. 완료 정산은 용암 보상 함수와 용암 코인 상한으로 흐름 | **REPLACE/EXTEND**. 심해 Stage별 비용·상한·아이템 허용 풀과 공통 결제·정산 분리 |
| 도감·저장 | 현재 런의 발견 ID는 Scene/Host 상태뿐. 영구 바닷속 보물도감 필드 없음 | **NEW** 별도 도감 ID·저장·마이그레이션. 공룡도감은 건드리지 않음 |
| 유물 | `deepSeaCanyon` 5부품·완성 이미지 및 공통 진행 필드 존재. 앱의 지급 분기는 용암·하늘섬만 연결 | 정의·저장 **REUSE**, Stage 3 클리어 전용 지급·2회 후 확정 정책 **EXTEND** |

특히 유료 입장으로 바꿀 때는 **표시 가격과 실제 차감이 달라질 위험**이 있다. 현재 `App.startAdventureGame()`은 심해의 `MINIGAME_ENTRY_COST`를 표시하지만, `chargeMinigameEntry()`는 심해를 `ancientRuins` 기본 지역으로 매핑한다. 현재 두 곳 모두 0원이라 드러나지 않는다. Phase 9에서 심해 지역 ID를 명시하고 표시·차감·재도전 가격을 같은 함수로 계산해야 한다. 현행 `applyLavaValleyRewards()` 역시 `lavaValley | skyIsland`만 받으므로 심해 정산을 그대로 통과시키면 용암 상한과 빈 아이템 풀을 사용한다.

| --- | --- | --- |
| 26×26 / 30×30 / 36×36~40×40과 3~10분 탐험 | 16~18 / 20~24 / 22~26 타일, Stage 1/2/3 한 판 1~2 / 2~3 / 3~4분 | 이전 크기·시간은 과거 목업 기록. 새 맵 생성·카메라 기준으로 교체 |

| Stage 3 여러 맵팩·Final Map | Stage당 한 판을 템플릿 조합으로 변형, 5부품 뒤 유물보관소 복원 | 맵팩·Final Map은 보류 |

| `resolveRegionFinalChest`의 2회 뒤 70%, 3회 뒤 확정 | 심해는 2회 연속 실패 뒤 다음 클리어 확정 | 공통 함수의 지역별 정책 분리 필요 |

문서별로 보면 [전체 기획](./deep-sea-game-design.md)은 장르·플레이 시간·Stage 3 맵팩/Final Map·하트, [Stage 2 레벨 설계](./deep-sea-stage2-level-design.md)는 36×36·다섯 구역·중앙 닻, [Stage 2 구현 계획](./deep-sea-stage2-implementation-plan.md)은 대형 맵·소나·탐험 미니맵을 과거 기준으로 남긴다. [Phaser 계획](./deep-sea-phaser-plan.md)의 카메라·타일 이동 구조는 참고하되 fog·소나·맵팩·하트 규칙은 교체한다. [목업 계획](./deep-sea-mockup-plan.md)의 한 고정 맵, 3~7분, 탐험 관찰 항목은 새 아케이드 아이 테스트 기준으로 다시 쓴다. 기존 파일 자체는 변경하지 않는다.

## 필요한 신규 에셋

현재 심해 플레이 화면은 주로 Phaser 도형이며, [기존 유물 이미지](../src/assets/adventure/relics/index.ts)는 유물보관소용이다. 최근 컨셉 스냅샷은 **세로 iPad·팩맨식 미로·잠수함 추적·빛나는 파워업·간단한 미니맵**의 분위기 참고로만 사용하며 게임 에셋으로 직접 넣지 않는다.

| 우선순위 | 제작 목록 | 제작·성능 기준 |
| --- | --- | --- |
| 필수 플레이 | 잠수함 정상·경미 파손·심각 파손 3장, 상어·문어와 도주/기절 표시, 전기 구슬·강화 잠수함 표시, 출구 잠김/열림, 목표 보물, 통로 코인 | 동일 anchor·충돌 크기. 잠수함 회전 시 무늬가 어색하지 않게. 큰 필터 대신 프레임·색·짧은 tween |

## Arcade Redesign Implementation Roadmap

각 Phase는 다음 Phase의 규칙을 가정하지 않고 작은 플레이 가능한 판과 검증 결과를 남긴다. 에셋이 늦으면 도형 목업으로 규칙을 먼저 검증하고, iPad Pro 1세대에서 입력 반응·메모리·프레임 안정성을 확인한다.

| Phase · 구현 목표 | 재사용 코드 | 신규 코드 | 필요한 에셋 | 검증 방법 | iPad Pro 1세대 고려 |
| --- | --- | --- | --- | --- | --- |
| **1. 통로 이동·맵 시제품**: 4방향 연속 이동, 예약 회전, 목표 3개·출구를 가진 짧은 고정 판 | Scene, 타일 좌표·벽 판정, Host, 출구 콜백 | `queuedDirection`, 목표/출구 규칙, 새 Stage config | 임시 통로·잠수함·목표·출구 | 교차로 직전/반대 입력, 벽 충돌, 목표 3개 뒤 출구, 1~2분 동선 | 입력을 React 매 프레임 state로 보내지 않음; 카메라 35~50%와 터치 크기 실기기 확인 |

**출시 전 통과 조건:** 통로·목표·출구 자동 검증, 아이가 적의 행동과 파손 상태를 읽는지 확인, 짧은 판의 실제 중앙 플레이 시간, 코인 순손실 경제 시뮬레이션, Stage 3 유물 중복·pity·복원 테스트, iPad Pro 1세대 Safari의 입력·카메라·30fps 안정성을 모두 확인한다. 60fps는 이상적 목표이고 구형 기기에서 안정적인 30fps와 조작 반응을 우선한다. 에셋은 표시 크기에 맞춰 디코드 메모리를 확인하며, 과한 파티클·필터와 매 프레임 React HUD 갱신을 피한다.
