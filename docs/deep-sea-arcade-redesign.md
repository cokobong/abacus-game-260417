# 심해협곡 아케이드 최종 기획

## 문서 지위와 게임 정의

**이 문서는 심해협곡의 최우선 구현 기준이다.** [기존 전체 기획](./deep-sea-game-design.md), [Stage 2 레벨 설계](./deep-sea-stage2-level-design.md), [Stage 2 구현 계획](./deep-sea-stage2-implementation-plan.md), [Phaser 계획](./deep-sea-phaser-plan.md), [목업 계획](./deep-sea-mockup-plan.md)은 삭제하지 않고 탐험형 시안의 참고자료로 보존한다. 충돌하는 규칙·수치·용어는 이 문서를 우선한다. 이 문서의 **목표 설계**와 **현행 구현**은 아래에서 구분한다.

2026-09-18 기준 실제 Stage 1~3 코드·placeholder 현황과 맵/에셋 확장안은 [에셋 조사 및 제작 계획](./deep-sea-arcade-asset-plan.md)을 따른다. 이 문서 아래의 Stage 3 작업 경계는 구현 전 계획을 기록한 것이다.

> 잠수함으로 해저 통로를 이동하면서 코인과 바닷속 보물을 수집하고, 움직이는 적을 피하거나 전기 구슬로 역전시키며, 목표 보물 3개를 모은 뒤 출구로 탈출하는 팩맨형 심해 아케이드 게임.

진행 순서는 **Stage 1-1 → 1-2 → 1-3 → Stage 2 → Stage 3**이다. 짧고 반복 가능한 미니게임으로 유지한다. 긴 탐험, RPG 성장, 새 조작 체계, 복잡한 퍼즐로 확장하지 않는다. Stage 2의 플레이 가능한 런타임을 Stage 1과 3에서도 설정을 바꿔 재사용한다.

| 구간 | 목표 플레이타임 | 핵심 경험 | 현행 상태 |
| --- | --- | --- | --- |
| Stage 1-1 | 45~60초 | 4방향 Stop & Go, 예약 회전, 코인, 출구 | 아케이드 튜토리얼 시제품 |
| Stage 1-2 | 60~90초 | 상어, 피격·무적, 전기 구슬, 강화·도주 | 아케이드 튜토리얼 시제품 |
| Stage 1-3 | 90초~2분 | 상어·문어, 목표 보물 3개, 출구 활성화·탈출 | 아케이드 튜토리얼 시제품 |
| Stage 2 | 약 2~3분 | 모든 기본 규칙을 한 판으로 반복 | 22×22 고정 맵 아케이드 시제품 |
| Stage 3 | 약 3~4분 | 더 넓은 맵, 세 적, 전략적 전기 구슬, 주기 수문 | 26×26 템플릿 4종 아케이드 구현; 실기기 플레이 검증 전 |

시간은 아이 플레이 테스트의 목표 범위다. 기본 규칙에 시간 초과 실패 조건은 없다. Stage 3이 4분을 자주 넘으면 맵·동선을 줄인다.

## Stage 1: 실제 플레이 튜토리얼

Stage 1은 별도 장르나 별도 이동 엔진이 아니다. Stage 2의 타일 이동, 벽 판정, 예약 회전, 픽업, 적, 전기 구슬, 카메라와 출구를 미션 설정에 따라 켜거나 끈다.

- **1-1:** 작은 통로에서 코인 목표를 채우면 출구가 열린다. 적·피해·전기 구슬·보물은 없다.
- **1-2:** 느린 상어와 전기 구슬을 만나고, 강화 중 적의 도주와 접촉 역전을 배운다. 피격 시 잠깐 무적이다. 보물은 없다.
- **1-3:** 상어·문어·전기 구슬·코인과 목표 보물 3개를 함께 경험한다. 세 번째 보물 뒤 출구가 열리고 실제로 도착해야 끝난다.

첫 이동, 교차로, 코인, 적 접근·피격, 전기 구슬, 첫 보물, 출구 활성화에 1~2줄짜리 상황 팝업을 한 번씩 보여준다. 팝업 동안 Scene 시간과 이동을 멈춘다. **현행은 세션 수준의 `seenTutorialIds`와 미션 내부 순서**를 사용하고, 1-3 클리어 때 공통 Stage 1 완료 저장 및 Stage 2 해금을 호출한다. 미션별 영구 저장·건너뛰기는 후속 작업이며 이미 구현된 것으로 간주하지 않는다. 이전 탐험형 Stage 1 Host·Scene은 삭제하지 않고 참고용으로 보존한다.

## Stage 2: 본게임 기준

**현행 Stage 2의 22×22 고정 통로 맵과 플레이 감각을 기준으로 고정한다.** Stop & Go, 타일 중심 예약 회전과 즉시 반전, 추적 카메라, 상어 2마리·문어 1마리의 타일 경로 이동, 전기 구슬 2개와 약 7초 강화, 목표 보물 3개, 출구, 통로 코인, 미니맵, 3단계 잠수함 파손과 약 1.3초 무적, 클리어 코인 정산이 있다. 카메라 확대값은 Stage 1 **1.54**, Stage 2 **1.65**, Stage 3 **1.60**이다. 보행 칸은 Stage 배경을 바닥으로 쓰며 바닥 타일 이미지를 반복하지 않는다.

보물 3개를 얻으면 월드 출구·HUD·미니맵이 열린 상태를 알려준다. 출구에 닿아야 클리어하며 모든 코인을 먹을 필요는 없다. 시작점 가까운 보물 하나, 중간 동선 하나, 먼 동선 하나로 위험을 나눈다. 현행 고정 배치를 다시 큰 맵 생성기로 갈아엎지 않는다. 적 스폰과 코인·보물·전기 구슬·출구의 동일 타일 겹침, 접근 가능성, 스폰 거리와 보물 간격을 검사한다.

상어는 순찰·추격·복귀, 문어는 진행 방향의 교차로 압박으로 역할을 구분한다. 전기 구슬 중 적은 도망가고 닿으면 기절했다가 안전하게 재등장한다. 강화 종료 직후 짧은 보호시간과 접촉 유지 중 반복 피격 방지를 유지한다. 잠수함 상태는 `normal / damaged / critical / failure`로 표시하며 하트 HUD를 최종 방향으로 확대하지 않는다. 미니맵은 통로·플레이어·잠김/열림 출구를 간결하게 보여주고 적 위치를 실시간으로 표시하지 않는다.

Stage 2의 조작·AI·맵을 Stage 3 구현을 위해 대규모로 다시 쓰지 않는다. 화면 크기·이동 감각·실제 중앙 플레이타임은 iPad 실기기에서 확인한다.

## Stage 3: 최종 강화 아케이드

> **Stage 2의 팩맨형 규칙에 조금 더 넓은 검증된 맵, 상어·문어·해파리, 전략적인 전기 구슬, 주기적으로 열리고 닫히는 심해 수문을 더한 최종 판.**

Stage 2와 같은 런타임·4방향 입력·보물 **3개 → 출구 활성화 → 실제 탈출** 규칙을 쓴다. 보물 수를 늘려 난이도를 만들지 않는다. 권장 맵은 **24×24~26×26**, 플레이타임은 **3~4분**, 적은 세 종류, 전기 구슬은 **1~2개**, 수문은 **2~3개**다. 미니맵과 카메라 추적도 유지한다. 길어진 직선 통로나 30×30 이상의 탐험 맵, 5~7분 플레이, 새 버튼, 퍼즐방은 제외한다.

| 역할 | Stage 3 행동 |
| --- | --- |
| 상어 | 적극 추격. `PATROL → CHASE → RETURN`으로 직접적인 압박을 만든다. |
| 문어 | 진행 방향과 교차로를 읽고 차단·매복하되 완전 봉쇄는 피한다. |
| 해파리 | 느리게 순찰하는 제어형 적. 직접 피해 없이 접촉 시 잠수함 이동을 기본 1.8초 멈추게 한다. 상어·문어의 피해 판정은 유지하며, 강화 중에는 붙잡지 않고 해제 후 재접촉 유예를 둔다. |

보물 A는 비교적 안전한 곳, B는 적 이동이 잦은 중간 위험 구역, C는 수문·적 동선이 얽힌 곳에 둔다. 셋은 충분히 떨어뜨리되 막다른 길 깊숙한 곳만 강제하지 않는다. 어떤 보물도 적·전기 구슬·출구와 같은 타일에 놓지 않고, 문이 닫혀도 접근 가능해야 한다. 마지막 보물에서 출구까지는 실제 복귀 판단이 있지만 긴 역주행은 피한다.

전기 구슬 지속시간의 기본값은 Stage 2처럼 **약 7초**다. Stage 3에서는 위험한 보물을 먼저 가져갈지, 출구 복귀에 쓸지 선택할 수 있게 배치한다. 지속시간과 스폰 수는 설정으로 조정한다.

### 슬라이딩 심해 수문

수문은 **열림 → 닫힘 예고 → 닫힘 → 일정 시간 유지 → 다시 열림**을 반복한다. 즉사 함정이 아니라 동선을 바꾸는 장치다. 경고에는 형태·빛과 짧은 소리를 함께 쓰고, 닫힘 시점을 눈으로 예측할 수 있어야 한다. 수문이 차지한 타일에 잠수함이나 적이 있으면 닫힘을 늦추거나 안전하게 통과를 마무리한다. 벽에 끼이거나 닫히는 순간 피해를 받지 않는다.

수문은 잠수함과 적의 통행 그래프에 **동일하게** 적용한다. 상어 추격도 문에 막히고, 문어와 해파리도 열려 있는 우회로를 사용한다. 문 상태가 바뀔 때 경로를 다시 판단하되 매 프레임 무거운 탐색은 하지 않는다. 모든 닫힌 상태에 보물과 출구로 가는 대체 경로가 있어야 하며, 기다림만이 유일한 해법이 되어서는 안 된다. 미니맵에는 열림/닫힘만 작은 표식으로 보여준다.

- **Gate A:** 읽기 쉬운 고정 주기의 기본 수문.
- **Gate B:** 열려 있는 시간이 조금 짧은 위험 구간용 수문. 경고 시간은 줄이지 않는다.
- **Gate C 후보:** 보물 획득·진행 단계 이후 활성화. 초기 Stage 3 구현에서는 보류한다.

수문 주기·예고·닫힘 시간은 맵 템플릿별 설정값으로 두고 완전 랜덤 즉시 닫힘은 금지한다. 한 맵에 2~3개만 사용한다. 적을 문 너머에 잠깐 묶어 플레이어에게 유리한 기회도 생기게 한다.

### 한 판의 흐름

초반에는 안전한 첫 보물과 수문 1개의 예고를 본다. 중반에는 상어·문어와 두 번째 보물, 우회 판단을 경험한다. 후반에는 해파리와 세 번째 보물·수문 조합이 겹친다. 보물 3/3 뒤 출구가 열리고 실제로 돌아가 탈출하면 결과 화면에서 코인·신규 도감 기록·일반 클리어 보상과 유물부품 추첨 결과를 보여준다.

## 맵 템플릿·반복 플레이

Stage 2의 고정 맵은 유지한다. Stage 3에는 완전 랜덤 벽 생성 대신 **직접 검증한 4~6개 맵 템플릿과 각 템플릿의 스폰 후보 풀**을 사용한다. 후보 테마는 루프형, 중앙 교차형, 좌우 우회형, 수문 중심형, 외곽 순환형, 복수 루프형이다. Stage 2 템플릿 2~3종 확대는 후속 선택 사항이며 Stage 3의 선행 조건이 아니다.

각 템플릿에는 `playerStart`, `treasureSpawnCandidates`, `enemySpawnCandidates`, `powerupSpawnCandidates`, `gatePositions`, `exitCandidates`, `coinPathCandidates`를 정의한다. 런 시작 때 템플릿을 고르고, 보물 후보 3개·적 시작점·전기 구슬 1~2개·출구·수문 패턴/시작 위상·코인 경로를 **후보 안에서만** 선택한다. 같은 템플릿도 보물·적·구슬·출구·수문 위상·코인 위치로 차이가 난다. 선택 결과와 seed는 한 런 동안 고정해 재시작·보상 재호출 시 달라지지 않게 한다.

시작 전 검증은 다음을 모두 통과해야 한다.

1. 시작점에서 보물 3개와 출구에 도달하고 고립된 필수 바닥 구역이 없다.
2. 수문이 모두 닫힌 상태에서도 필수 보물과 출구에 우회로가 있다. 수문 하나가 유일한 필수 경로가 되지 않는다.
3. 플레이어와 적 시작점 사이에 안전거리가 있고, 시작 즉시 충돌하거나 막다른 통로에서 피할 틈 없이 맞지 않는다.
4. 적·코인·보물·전기 구슬·출구·시작점이 같은 타일에 겹치지 않는다. 보물 3개는 한 구역에 몰리지 않는다.
5. 출구 앞을 적 스폰이나 닫힌 수문이 영구 봉쇄하지 않는다. 세 번째 보물 뒤 출구까지 과도한 되돌아가기가 없다.
6. 수문 전환 시 점유자 끼임이 없고 적과 플레이어에게 같은 통행 규칙이 적용된다.

실패한 조합은 정해진 재시도 횟수 안에서 다시 뽑고, 계속 실패하면 검증된 예비 배치를 사용한다. 실패 사유·템플릿 ID·seed를 남겨 재현한다. 생성·검증은 판 시작 때만 수행하며 프레임마다 맵을 다시 만들지 않는다. 적 경로는 기존 타일 그래프의 교차로/타일 경계 갱신을 확장한다. 복잡한 A* 의존은 기본 설계가 아니다.

## 코인·바닷속 보물·결과

**목표 보물 3개**는 출구 조건이고, **선택 도감용 바닷속 보물**은 영구 수집 기록이다. 두 시스템의 ID·HUD·보상은 분리한다. Stage 1-1/1-2는 배운 규칙에 맞는 간단한 목표를 쓰고, 1-3/2/3에서는 3개 규칙을 유지한다. 도감용 보물은 한 판에 1~3개를 후보 풀에서 발견하게 하는 후속 설계이며 **현행 아케이드에는 영구 도감이 없다**.

| Stage | 도감용 보물 풀 초안 |
| --- | --- |
| 1 | 오래된 나침반, 녹슨 배 열쇠, 조개 목걸이, 금빛 동전, 병 속의 지도, 작은 선장 장식 |
| 2 | 그림 돌판, 금빛 항아리, 부서진 왕관, 물고기 그림 접시, 빛나는 돌상, 별 금속 조각, 파란 보석 상자, 옛날 종 |
| 3 | 세 갈래 창, 푸른 수정, 황금 물고기상, 해마 왕관, 빛나는 진주, 별빛 보석, 바다왕의 금 열쇠, 파란 눈 보석, 황금 소라, 조개 왕관 |

이름·이미지·희귀도는 도감 제작 때 확정한다. 화면에는 “바닷속 보물”과 쉬운 물체 이름을 쓴다. 중복 도감 보물은 신규 발견으로 세지 않고 소량 코인으로 바꾸되 한 판 정산 상한 안에 넣는 안을 유지한다. 실패/중단 시 신규 도감 발견은 유지하고 지갑 코인·아이템·유물부품은 지급하지 않는 안이다. 도감 독립 저장과 실패 시 기록 커밋은 **아직 구현되지 않았으므로** 구현 단계에서 저장 경로를 확인한다. 공룡도감과 저장 필드를 섞지 않는다.

주산 훈련이 코인의 기본 공급원이고 심해협곡은 선택 소비 콘텐츠다. 아래 수치는 현행 입장료 0과 다른 **경제 제안값**이며 훈련 보상·실제 플레이 결과와 함께 확정한다.

| 구간 | 입장료 제안 | 클리어 판 지갑 코인 상한 제안 | 목표 평균 회수 |
| --- | ---: | ---: | ---: |
| Stage 1-1~1-3 묶음 | 60, 첫 입문 1회 무료 가능 | 합계 30 | 10~20 |
| Stage 2 | 90 | 45 | 20~30 |
| Stage 3 | 120 | 60 | 30~45 |

입장료보다 정산 상한을 낮게 잡고, 코인은 결과에서 `runId`당 한 번만 지급한다. Stage 1 묶음 재시도 비용과 첫 무료 입문 기록은 경제 구현 전 결정한다. 현행 심해 코인 정산은 [별도 시제품 함수](../src/config/minigameConfig.ts)를 사용하며, 유료 입장·도감·Stage 3 보상은 연결되지 않았다.

### Stage 3 유물부품

유물부품은 **Stage 3 출구 탈출 클리어 후에만** 추첨한다. 판 중 스폰하지 않고, Stage 1/2 클리어·Stage 3 실패·중단에는 추첨이 없다. 기본 확률 시작값은 **37.5%**, 이미 가진 부품은 후보에서 제외, **연속 2회 미획득 뒤 다음 Stage 3 클리어에서 확정**한다. 획득 시 미획득 연속 횟수를 0으로 돌린다. 정확한 값은 지역별 config로 분리한다.

기존 [심해협곡 지역 유물 정의](../src/config/regionalRelicConfig.ts)와 [유물 진행 저장](../src/config/worldMapRelicConfig.ts)의 다섯 부품·완성 이미지를 재사용한다. 5개를 모으면 유물보관소에서 **심해왕의 진주 성배**를 복원한다. 도감 보물과 유물부품은 별도 ID·UI다. 현행 공통 `resolveRegionFinalChest()`는 2회 미획득 뒤 70%, 3회 뒤 다음 회차 확정이라 이 기준과 다르다. 심해 전용 확률·pity 정책을 추가하되 다른 지역 규칙은 바꾸지 않는다. 현행 `App.tsx`에는 심해 Stage 3 지급 연결이 없다.

## 구현 현황과 Stage 3 작업 경계

| 영역 | 현행 | Stage 3에서 할 일 |
| --- | --- | --- |
| 진입·진행 | [AdventureGameShell](../src/components/screens/AdventureGameShell.tsx)이 Stage 1/2를 공통 아케이드 Host에 연결. 1-3 완료 후 공통 Stage 2 해금. 카탈로그의 Stage 3은 미구현 | Stage 3 선택·진입·완료 연결 |

| 적·전기 | 상어·문어 경로 이동, 7초 강화, FLEE·기절·안전 재등장 | 해파리 1종과 수문 상태에 맞춘 공통 경로 판단 |
| 피격·출구·카메라 | health 3, 짧은 무적, 보물 3개 뒤 출구, Stage 2 zoom 1.18 | 그대로 재사용하고 Stage 3 크기에 맞춰 값만 튜닝 |
| 미니맵·HUD·결과 | 통로·잠김/열림 출구·플레이어 표시, 코인·보물·파손·강화 HUD, 클리어/실패 결과 | 수문 상태와 Stage 3 유물 결과를 추가 |
| 코인·도감·유물 | 심해 입장료 0과 클리어 코인 상한. 영구 바닷속 보물도감 없음. 유물 부품 정의·진행 필드만 존재 | 경제 확정 후 Stage별 결제·정산, 도감 저장, 클리어 전용 유물 지급 연결 |
| 이전 탐험형 코드 | [DeepSeaGameHost](../src/components/screens/DeepSeaGameHost.tsx), [createDeepSeaGame](../src/components/screens/deepSea/createDeepSeaGame.ts), 과거 stage1/stage2 config에 fog·소나·상자·수리 등이 남아 있음 | 삭제·이식하지 않고 참고용 보존 |

Stage 3 설정은 기존 deep-sea 설정 구조에 통합한다. 최소 항목은 `mapTemplatePool`, `mapSize`, `treasureCount=3`, `treasureSpawnCandidates`, `enemySpawnCandidates`, `powerupCount`, `powerupDuration`, `gateCount`, `gateCycle`, `gateWarningDuration`, `gateClosedDuration`, `gatePatternPool`, `enemySpeed`, `sharkChaseRange`, `jellyfishSpeed`, `spawnSafetyDistance`, `exitCandidates`, `relicDropChance`, `relicPityThreshold=2`, `validationRetryCount`다. Stage 2의 이동·충돌·코인·보물·출구·강화·피격·카메라·미니맵·HUD·결과 흐름은 재사용한다.

구현 순서는 **공통 Stage 설정 및 첫 검증 맵 → 수문 상태/통행 검증 → 해파리 → 후보 풀과 나머지 템플릿 → Stage 3 결과·유물 연결 → 실기기 난이도·시간 확인**이다. 같은 시점에 경제·도감 저장 정책을 연결해야 보상 중복이나 실패 보상 누수를 막을 수 있다. 구형 iPad에서는 맵 생성은 시작 때 한 번, 적 경로 갱신은 타일 경계 중심으로 유지하고 과한 필터·파티클·매 프레임 React HUD 갱신을 피한다.

## 에셋 요구 초안

현재 아케이드의 잠수함·상어·문어·전기 구슬·보물·출구·벽·통로·코인은 Phaser 도형이다. 공통 심해 UI 패널과 유물 다섯 부품·완성 이미지는 이미 있다. **Stage 1~3 전체 최종 에셋 목록과 실제 파일명은 Stage 3 코드 구현 후 추출·확정한다.** 이번 단계에서는 이미지를 제작하지 않는다.

| 구분 | Stage 3 신규 후보 |
| --- | --- |
| 적 | 해파리와 이동·도주·기절 표현 |
| 수문 | 고대 슬라이딩 수문 열림·예고·닫힘, 경고등/효과 |
| 보물·장면 | Stage 3 보물 변형, 입장·결과 화면 |
| 보상 | 유물 보상 상자/효과가 필요한지 구현 후 판단 |
| 미니맵 | 열림/닫힘 수문 표식 |

기존 Stage 1/2의 잠수함 파손·강화, 상어·문어, 목표/선택 보물, 월드 타일과 HUD 아이콘은 후속 전체 에셋 목록에서 함께 정리한다. 작은 화면 가독성과 iPad 메모리를 기준으로 크기와 아틀라스 구성을 결정한다.
