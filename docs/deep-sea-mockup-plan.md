# 심해협곡 Stage 1/2 목업 계획

## 1. 목업 목적

목업은 미술 품질이 아니라 탐험 재미와 어린이의 이해도를 확인한다. 실제 에셋을 제작하지 않고 도형, 단색 타일, 문자 아이콘으로 Stage 1과 Stage 2 각각 한 맵만 만든다.

검증 질문은 다음과 같다.

- 아이가 설명 없이 4방향 이동을 시작하는가?
- 큰 맵에서 길을 잃는 경험이 호기심인지 좌절인지?
- 발견물 접근과 자동 등록을 이해하는가?
- 목표 충족 뒤 출구가 열린 것을 알아차리는가?
- Stage 2 제한 시야와 소나를 스스로 활용하는가?
- 위험 회피가 불공정하지 않고 긴장을 주는가?

## 2. 공통 목업 표현

| 요소 | 임시 표현 |
|---|---|
| 바닥/벽 | 색이 다른 사각 타일 |
| 잠수정 | 방향 삼각형이 있는 밝은 원 |
| 미발견 영역 | 반투명 검정 마스크 |
| 발견물 | 카테고리별 색 원과 짧은 라벨 |
| 보물상자 | 금색 사각형 |
| 출구 | 잠김/활성 색이 다른 큰 링 |
| 상어 | 이동 방향이 표시된 붉은 마름모 |
| 문어 | 경고 반경이 있는 자주색 원 |
| 소나 | 확장하는 원형 선 |

임시 그래픽은 한눈에 기능을 구분할 수 있어야 하지만 실제 아트 방향을 확정하지 않는다.

## 3. Stage 1 목업 맵

### 사양

- 기준 크기: 26×26
- 목표 플레이 시간: 3~5분
- 시야 반경: 화면에서 다음 갈림길 하나 이상이 보이는 수준
- 위험: 첫 테스트는 없음, 탐험이 지나치게 평면적일 때 느린 순찰 상어 1마리 추가
- 발견물: 산호 군락, 오래된 석상, 보물상자
- 출구 조건: 3개 중 2개 발견

### 맵 구조

- 입구 구역: 이동과 첫 발견물을 안전하게 익히는 짧은 통로
- 중앙 허브: 세 갈래가 보이는 기억 지점
- 산호 구역: 입구에서 비교적 가까우며 첫 자동 발견 후보
- 유적 구역: 방향을 두 번 이상 선택해야 도달
- 보물 구역: 막다른 길 끝이지만 중앙으로 돌아가는 지름길 제공
- 출구 구역: 초반에 잠긴 상태를 볼 수 있고 조건 달성 후 되돌아오기 쉬운 위치

최단 동선만 따라가도 맵 전체의 절반 이상을 보게 하되, 필수적인 장거리 백트래킹은 만들지 않는다.

### 계측

- 첫 이동까지 걸린 시간
- 첫 발견까지 걸린 시간
- 방문한 고유 타일 비율
- 방향 전환 실패 또는 벽 밀기 횟수
- 발견 목표 2개 달성 시간
- 출구 활성화 후 출구 도달 시간
- 힌트 요청 횟수

## 4. Stage 2 목업 맵

### 사양

- 기준 크기: 30×30
- 목표 플레이 시간: 5~7분
- 제한 시야: Stage 1보다 명확히 좁게
- 소나: 3회
- 위험: 상어 순찰 1마리, 문어 매복 1마리
- 하트: 3개
- 필수 목표: 예를 들어 오래된 항해 표식과 난파선 기록 모두 발견
- 선택 목표: 희귀 발광 생물 발견, 숨은 보물상자 개봉

### 맵 구조

- 초반 안전 구역에서 소나 버튼을 보여주되 강제 사용시키지 않는다.
- 첫 필수 목표는 소나 없이도 랜드마크 단서로 찾을 수 있다.
- 두 번째 필수 목표는 좁은 시야 때문에 탐색이 필요하되 막다른 길 연속을 피한다.
- 상어 순찰 구역은 우회 통로가 있고 이동 패턴을 관찰할 안전 지점을 둔다.
- 문어 매복 전에는 바닥 색 또는 경고 범위로 예측 단서를 준다.
- 희귀 발견과 보물상자는 필수 경로에서 한 갈림길 더 들어간 위치에 둔다.
- 출구 활성화 뒤 긴 귀환이 필요하면 일방 지름길을 개방한다.

### 소나 목업 규칙

- 버튼에 남은 횟수 3/3을 항상 표시한다.
- 사용 시 약 1~1.5초 동안 시야 반경이 확대된다.
- 미발견 필수 목표가 있으면 정확한 위치가 아닌 방향성 신호만 표시한다.
- 소나 사용 중 이동과 위험 AI는 계속된다.
- 횟수가 0이면 버튼 상태와 피드백으로 즉시 알린다.

### 계측

- 소나 최초 사용 시점과 총 사용 횟수
- 소나 없이 장시간 정체한 구간
- 위험 발견부터 회피 입력까지 시간
- 피격 원인과 위치, 남은 하트
- 필수/선택 목표 달성률
- 중단 또는 클리어 시간

## 5. 아이 테스트 진행

### 대상과 세션

- 첫 세션은 도움 없이 관찰하고, 막힘이 지속될 때만 정해진 힌트를 제공한다.
- Stage 1 뒤 짧은 질문을 하고 Stage 2를 이어서 플레이한다.
- 말로 설명한 내용과 실제 행동 로그를 함께 기록한다.

### 관찰 항목

- 방향 패드와 화면 속 잠수정 방향의 대응을 이해하는가?
- 교차로에서 원하는 방향으로 자연스럽게 전환되는가?
- 카메라 이동으로 멀미나 혼란을 느끼는가?
- 어두운 영역을 탐험 대상으로 이해하는가?
- 발견 팝업과 목표 체크 변화의 관계를 이해하는가?
- 잠긴 출구와 열린 출구를 구별하는가?
- 소나를 아껴야 하는 자원으로 이해하는가, 아예 잊는가, 연속으로 소모하는가?
- 상어 순찰과 문어 경고를 보고 회피 경로를 선택하는가?
- 하트 감소 원인을 이해하는가?
- 희귀 발견과 필수 목표를 구분하는가?

## 6. 조정 우선순위

1. 조작 실패와 충돌 판정
2. 목표와 출구 상태 이해
3. 길 찾기 좌절과 과도한 백트래킹
4. 시야와 소나 가독성
5. 위험 속도와 예고 시간
6. 보상량과 연출

아트 피드백은 기능 구분이 안 되는 경우만 반영하고 실제 에셋 요구사항으로 확대하지 않는다.

## 7. Stage 3 MVP 진입 합격 기준

다음 기준을 Stage 1/2 목업에서 충족한 뒤 Stage 3 제작으로 넘어간다.

- 테스트 참여자의 대부분이 별도 조작 설명 없이 30초 안에 이동한다.
- Stage 1에서 3개 중 2개 목표와 출구 활성화를 스스로 이해한다.
- Stage 1 중앙 완료 시간이 대략 3~5분 범위다.
- Stage 2에서 소나를 최소 1회 의미 있게 사용하고 남은 횟수를 이해한다.
- Stage 2 필수 목표 완료율이 높고 중앙 완료 시간이 대략 5~7분 범위다.
- 위험 접촉 원인을 플레이어가 설명할 수 있고, 피할 수 없었다는 반응이 반복되지 않는다.
- 하트 0 실패가 특정 좁은 통로나 스폰 지점에 편중되지 않는다.
- 필수 목표와 선택 목표가 시각적으로 구분된다.
- 구형 iPad Safari에서 안정적인 30fps, 조작 응답, 정상적인 pause/resume을 유지한다.
- 맵 교체가 scene 수정 없이 config와 타일 데이터 교체로 가능하다.
- 시작점에서 모든 필수 목표와 출구까지 도달 가능함을 자동 검증한다.

기준 미달 시 Stage 3 콘텐츠 양을 늘리지 않고 Stage 1/2의 입력, 목표 전달, 지도 구조부터 수정한다.

## 9. 구현 순서

1. config 타입과 Stage 1/2 임시 맵 데이터
2. React host와 AdventureGameShell 연결
3. 타일 이동, 충돌, 카메라 추적
4. 제한 시야와 방문 기록
5. 발견물, 목표, 출구
6. 하트와 Stage 1 선택적 느린 적
7. Stage 2 소나
8. 상어 순찰과 문어 매복
9. 보물상자와 결과 정산
10. 로직 테스트와 iPad 수동 테스트

실제 에셋 제작과 Stage 3 구현은 이 목업 검증 이후 별도 작업으로 진행한다.
