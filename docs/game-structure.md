# 게임 전체 구조

이 문서는 새 게임의 큰 구조를 정리한다.

기존 주산 문제 풀이의 핵심은 유지하되, 아이가 반복해서 접속하고 싶어지는 알 부화, 캐릭터 성장, 수집, 모험, 상점 구조를 붙인다.

## 1. 기본 방향

- 한 판의 학습은 짧게 끝나야 한다.
- 문제 풀이 보상은 캐릭터 성장과 연결한다.
- 화면은 터치 노트북에서 한눈에 이해되고 직접 누르기 쉬워야 한다.
- UI는 귀엽고 밝지만 너무 복잡하지 않게 유지한다.
- 알, 캐릭터, 성장, 놀이 요소가 직관적으로 보여야 한다.
- 초기 실행 환경은 일반 모바일 앱이 아니라 터치 노트북에서 실행하는 브라우저 기반 로컬 웹앱이다.
- 로컬 개발은 `localhost`, 배포는 Netlify 같은 HTTPS 웹 배포 환경을 우선한다.
- 추후 PWA 형태로 설치형 앱처럼 전환할 수 있도록 저장과 화면 구조를 준비한다.

자세한 실행 환경, 로컬 저장, PWA 확장 계획은 `app-runtime-plan.md`에서 관리한다.

## 2. 핵심 루프

기본 플레이 흐름:

```text
문제 풀이
→ 코인/보상 획득
→ 상점 또는 모험에서 알/알 조각 획득
→ 부화방에서 알 돌보기
→ 부화 완료 후 새 공룡 획득
→ 도감 정식 등록
→ 모험/상점으로 확장
→ 다시 문제 풀이
```

이 구조의 목적은 단순 문제풀이를 끝내고 나서도 아이가 보상을 확인하고, 다음 플레이 이유를 자연스럽게 느끼게 하는 것이다.

새 공룡 획득은 `공룡 직접 구매`가 아니라 `알 또는 알 조각 획득 → 부화 → 도감 해금` 구조를 기본으로 한다.
상점은 새 공룡을 바로 파는 곳이 아니라, 부화로 이어지는 재료와 알을 제공하는 공간이다.

## 3. 최종 게임 루프

최종 게임 루프는 주판 반복학습을 중심에 두고, 성장/수집/부화/모험이 그 반복을 계속하고 싶게 만드는 구조다.

```text
1. 주판 문제 20문제 1세트 풀이
2. 정확도/속도/연속 성공에 따라 코인과 EXP 획득
3. EXP로 현재 공룡 성장
4. 코인으로 음식, 코스튬, 알 조각, 부화 보조 아이템 구매
5. 알 조각 또는 알을 획득하면 부화장에 등록
6. 문제 풀이로 부화 게이지 증가
7. 부화 과정에서 알이 커지고 힌트가 공개됨
8. 부화 완료 시 랜덤 공룡 등장
9. 도감에 새 공룡 등록
10. 새 공룡을 우리 공룡 탭에서 다시 육성
11. 성장한 공룡으로 모험/보상/도감 확장
```

핵심 철학:

- 아이가 매일 작은 성취감을 느껴야 한다.
- 큰 보상은 며칠~몇 주 단위 목표로 둔다.
- 공룡은 사는 것이 아니라, 알을 얻고 부화시켜 만나는 존재다.
- 보상은 주판 반복학습을 대체하지 않고, 반복학습을 더 하고 싶게 만들어야 한다.
- 코인과 EXP는 문제 풀이 결과에서 시작되고, 상점과 성장 시스템은 그 결과를 쓰는 공간이다.
- 코스튬은 능력치보다 애착과 수집욕을 키우는 장기 코인 소모처로 둔다.

입력 우선순위:

1. 블루투스 주판 입력
2. 터치 화면 키패드 입력
3. 마우스 입력
4. 키보드 입력은 개발/보조용

기본 학습 흐름에서는 블루투스 주판이 주 입력 장치다.
블루투스 주판을 사용할 수 없을 때는 터치 화면 키패드를 예비 입력 수단으로 사용한다.

훈련 세션 진행 원칙:

- 현재 목업에서는 테스트 편의를 위해 미션/문제 카드를 사용자가 직접 클릭해 이동할 수 있다.
- 최종 구현에서는 한 문제를 정답 처리하면 짧은 정답 피드백을 보여준 뒤 자동으로 다음 문제로 넘어간다.
- 오답이면 같은 문제에 머물며 다시 시도할 수 있어야 한다.
- 정답 처리 후 다음 문제로 넘어갈 때 앱 내부 `inputValue`, 피드백 메시지, 제출 상태, Bluetooth confirm debounce/guard 상태를 초기화한다.
- 새 문제 시작 시 화면에는 `주판알을 답에 맞게 움직인 뒤 리턴 버튼을 눌러주세요.` 안내를 표시한다.
- 물리 주판 상태는 앱이 자동으로 바꿀 수 없으므로, 문제 전환은 앱 내부 입력 상태 초기화만 수행한다.

## 4. 새 공룡 획득 루프

새로운 공룡은 상점에서 이름과 모습을 보고 직접 구매하지 않는다.
아이는 알의 카테고리와 단서를 보고 기대감을 가진 뒤, 부화 완료 시점에 어떤 공룡인지 확인한다.

기본 획득 루프:

```text
20문제 세트 완료
→ 코인 획득
→ 상점에서 알/알 조각 구매 또는 모험에서 알 조각 획득
→ 부화방에 알 등록
→ 문제 풀이 세트 성공과 부화 보조 아이템으로 부화 게이지 증가
→ 부화 완료
→ 알 카테고리 안에서 랜덤 공룡 등장
→ 도감 정식 해금
```

핵심 원칙:

- 새로운 공룡은 상점에서 직접 구매하지 않는다.
- 상점에서는 공룡이 아니라 알 또는 알 조각을 얻는다.
- 알을 구매할 때 공룡 이름은 바로 공개하지 않는다.
- 알 구매/등록 단계에서는 `미확인 알`, `일반 알`, `희귀 알` 정도만 표시한다.
- 부화 중에는 실루엣, 힌트, 알 무늬, 발자국, 울음소리 같은 단서만 제공한다.
- 도감은 알 구매 시점이 아니라 부화 완료 시점에 정식 해금된다.
- 일반 알, 희귀 알, 특별 알은 각각 약 12종 내외의 후보 공룡을 가진다.
- 부화 완료 시 해당 카테고리 안에서 랜덤으로 공룡이 등장한다.

알 카테고리:

| 카테고리 | 사용 목적 | 초기 구현 여부 |
| --- | --- | --- |
| 일반 알 | 기본 수집과 초반 부화 | 우선 구현 |
| 희귀 알 | 장기 목표와 높은 기대감 | 우선 또는 2차 |
| 특별 알 | 미션, 모험, 특별 조건 보상 | 후속 |
| 이벤트 알 | 기간 한정 이벤트 | 후속 확장 |
| 전설 알 | 매우 장기적인 최고 희귀도 | 후속 확장 |

중복 스트레스 완화는 후속 버전에서 고려한다.
예를 들어 중복 방지, 미등록 공룡 우선 확률 보정, 보유 공룡 확률 감소, 중복 공룡의 성장 재료 전환을 검토한다.

## 5. 탭 구조

### 부화방

알을 돌보고 부화시키는 핵심 공간이다.

- 문제 풀이 세트 성공으로 부화 게이지 증가
- 부화 보조 아이템, 미션 달성, 모험 보상으로 부화 조건 보조
- 현재 알의 상태, 부화까지 남은 진행도, 필요한 행동을 표시
- 문제 풀이 보상과 부화 진행을 직접 연결
- 알이 부화하면 캐릭터가 등록되고 도감에도 반영
- 부화 중에는 공룡 이름을 공개하지 않고 실루엣, 알 무늬, 발자국, 울음소리 같은 단서를 보여줌
- 먹이와 쓰다듬기는 부화 후 성장/친밀도 중심으로 사용

### 놀이터

부화한 캐릭터와 상호작용하는 공간이다.

- 간단한 미니게임, 기분 회복, 친밀도 증가
- 캐릭터별 반응 차이를 줄 수 있음
- 먹이, 장난감, 쓰다듬기 같은 짧은 상호작용 제공
- 학습 화면에서 얻은 보상이 캐릭터와 노는 데 쓰이도록 연결

### 도감

발견한 알, 캐릭터, 진화형, 아이템을 기록하는 수집 시스템이다.

- 수집 욕구를 자극하는 핵심 장치
- 아직 발견하지 못한 캐릭터는 실루엣으로 표시
- 발견 조건, 진화 조건, 희귀도 등을 기록
- 알 구매 시점에는 도감이 완전히 열리지 않고, 부화 완료 시점에 공룡 카드가 정식 해금됨
- 자세한 내용은 `pokedex-adventure.md`에서 관리

### 모험

캐릭터를 보내 보상을 얻는 시간 기반 탐험 콘텐츠다.

- 지역별 탐험, 시간 기반 보상, 아이템 획득
- 도감과 연결해 새로운 알 조각이나 알 카테고리 힌트 획득 가능
- 캐릭터 특성에 따라 성공률이나 보상 차이를 줄 수 있음
- 자세한 내용은 `pokedex-adventure.md`에서 관리

### 상점

코인으로 아이템을 구매하는 공간이다.

- 처음에는 최소 아이템만 제공
- 먹이, 장난감, 꾸미기 아이템 등으로 확장 가능
- 음식은 배고픔, 행복, 체력, EXP 보조에 사용
- 코스튬은 능력치보다 외형, 애착, 수집욕 중심으로 사용
- 새 공룡을 직접 판매하지 않고 알 또는 알 조각을 판매
- 알 구매 시에는 공룡 이름 대신 알 카테고리와 미확인 상태를 표시
- 실제 게임 데이터는 나중에 TypeScript 데이터 파일에서 관리
- 자세한 기획 방향은 `shop-items.md`에서 관리

## 6. 1차 구현 범위 제안

처음부터 모든 탭을 완성하지 않는다.

1차에서는 다음 정도가 적당하다.

- 문제 풀이 보상과 코인 획득
- 부화방의 알 1개
- 기본 캐릭터 1종
- 일반 알 카테고리와 랜덤 부화 흐름
- 놀이터의 단순 상호작용 1~2개
- 도감의 발견/미발견 표시 틀
- 상점의 기본 아이템 3~5개 기획
- 음식/코스튬/알 조각/부화 보조 아이템의 데이터 구조 방향
- 터치 노트북 기준의 큰 버튼/탭/키패드 UI
- 브라우저 로컬 저장을 통한 앱 재실행 후 상태 복원

모험은 탭 구조와 데이터 방향을 먼저 잡고, 실제 시간 기반 보상은 이후 확장해도 된다.

## 7. 상태 관리 원칙

게임 상태는 화면 컴포넌트 안에 흩어두지 않고 중앙 `GameState` 형태로 관리한다.

- 앱 실행 시 저장된 `GameState`를 불러온다.
- `GameState` 변경 시 자동 저장한다.
- 저장 데이터에는 버전 필드를 둔다.
- 추후 데이터 구조가 바뀔 수 있으므로 migration 가능성을 고려한다.
- 모험 같은 시간형 퀘스트는 실제 백그라운드 타이머가 아니라 `startedAt`, `durationMs`, `endsAt`를 저장하고 앱 재실행 시 현재 시간과 비교한다.
- 부화장은 시간보다 문제풀이 진행도가 핵심이므로 `progress`, `requiredProgress`, `hintStage`, `status`를 저장한다.

자세한 저장 구조는 `app-runtime-plan.md`에서 관리한다.
