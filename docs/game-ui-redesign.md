# Game UI Redesign Plan

이 문서는 현재 연결된 기능을 유지한 채, 나중에 UI를 한 번에 정리하기 위한 리디자인 기준을 정리한다.

이번 문서는 설계 문서이며, App.tsx 대규모 수정이나 실제 UI 리팩터링을 수행하지 않는다. 대상 사용자는 어린이이고, 부모는 설정과 확인을 담당한다. 전체 톤은 어린이 대상 공룡 육성 모바일 게임에 맞춘다.

## 1. 전체 UI 리디자인 원칙

- 아이가 보는 화면은 한 번에 하나의 핵심 행동만 명확해야 한다.
- 개발용 정보와 아이용 정보는 분리한다.
- 문제 풀이 중에는 문제와 공룡 리액션이 중심이어야 한다.
- 스테이트 수치, 내부 stage id, raw log, localStorage 데이터는 기본 화면에 노출하지 않는다.
- 공룡, 알, 아이템, 도감은 아이가 만지고 보고 싶게 보여야 한다.
- 부모 설정은 설정 탭에만 두고, 훈련 중에는 요약만 보여준다.
- 최종 UI는 모바일/태블릿 사용을 기준으로 한다.
- 버튼은 크고 명확해야 하며, 스크롤은 최소화한다.
- 개발자용 정보는 접기 영역 또는 개발자 패널로 이동한다.

## 2. 훈련장 UI 방향

훈련장은 아이가 문제에 집중하고, 함께 훈련하는 공룡과 교감하는 화면이어야 한다.

### 최종 목적

- 문제가 가장 잘 보여야 한다.
- 한 번에 한 문제만 크게 표시한다.
- 아이가 물리 주판으로 문제를 풀고 리턴 버튼을 누르는 흐름이 명확해야 한다.
- 문제를 맞히면 공룡이 반응한다.
- 문제를 다 풀면 보상이 잘 보여야 한다.
- 훈련 중에는 공룡의 세부 상태 수치를 굳이 크게 노출하지 않는다.
- 경험치, 체력, 행복감, 배고픔 같은 스테이트는 문제 완료 후 결과/리액션 화면에서 보여준다.

### 훈련 중 화면 구조

#### A. 상단 영역

- 오늘의 주산훈련
- 현재 교재 단계 요약
- 문제 진행률: 문제 1/15
- 정답 수 / 오답 시도 수 정도만 간단히 표시
- 상태 수치 과다 노출 금지

#### B. 중앙 문제 카드

- 현재 문제 하나만 크게 표시
- 예: `8 + 5 - 3 + 2`
- 숫자와 연산자가 크고 읽기 쉬워야 함
- 문제 외 정보는 최소화

#### C. 함께 훈련하는 공룡 영역

- activeDinosaur가 함께 훈련하는 느낌을 준다.
- 정답 시 기뻐하는 리액션
- 오답 시 응원하는 리액션
- 연속 정답 시 더 큰 리액션
- 문제 풀이 중 공룡은 보조 역할이며, 문제 가독성을 방해하지 않아야 한다.

#### D. 주판 입력 안내

- “주판알을 답에 맞게 움직인 뒤 리턴 버튼을 눌러주세요.”
- Bluetooth 연결 상태 간단 표시
- 앱 테스트 입력은 개발자용 또는 숨김 처리

#### E. 피드백

- 정답: “맞았어요!”
- 오답: “다시 해볼까요?”
- 정답 후 짧은 시간 뒤 다음 문제로 이동
- 오답 후 같은 문제를 다시 풀 수 있음

### 훈련 완료 화면

문제를 모두 맞히면 결과와 보상이 잘 보여야 한다.

표시 요소:

- 훈련 완료
- 총 문제 수
- 정답 수
- 오답 시도 수
- 정확도
- 획득 코인
- 획득 경험치
- 획득 부화 아이템
- 함께 훈련한 공룡의 리액션
- 공룡의 경험치/체력/행복감 변화

중요:

- 스테이트 수치는 훈련 중보다 완료 후 화면에서 보여주는 것이 좋다.
- 아이가 “공룡이 나와 같이 훈련해서 성장했다”는 느낌을 받아야 한다.

버튼:

- 다시 훈련하기
- 우리 공룡 보러가기
- 알 부화장 가기

## 3. 우리 공룡 탭 UI 방향

우리 공룡 탭은 보유한 공룡을 중심으로 교감하고 꾸미는 화면이다.

### 최종 목적

- 공룡이 화면 중앙에 크게 보여야 한다.
- 아이가 현재 선택한 공룡과 교감하는 느낌을 받아야 한다.
- 상태 수치는 작고 간단하게 보여준다.
- 먹이, 코스튬, 아이템 적용이 잘 보여야 한다.
- 공룡 선택은 좌우 화살표 또는 carousel 방식으로 한다.

### 화면 구조

#### A. 중앙 공룡 영역

- 현재 선택된 공룡이 중앙에 크게 위치
- 이름, 레벨, 간단한 상태 표시
- 좌우 화살표로 보유 공룡 변경
- 공룡의 표정/리액션을 나중에 추가 가능하게 설계

#### B. 상태 정보

- 경험치
- 행복감
- 체력/에너지
- 배고픔/포만감
- 단, 너무 크게 강조하지 않는다.
- 수치보다 아이가 이해하기 쉬운 아이콘/바 형태 권장

#### C. 먹이 영역

- 보유 먹이가 잘 보여야 한다.
- 먹이를 선택하고 적용하는 흐름이 명확해야 한다.
- 먹이 적용 후 공룡 리액션 표시
- 수량 표시

#### D. 코스튬 영역

- 보유 코스튬이 잘 보여야 한다.
- 장착/해제 상태가 명확해야 한다.
- 부위별 슬롯: 머리, 목, 몸, 액세서리
- 같은 코스튬을 여러 공룡이 동시에 착용 가능하다는 기존 정책 유지

#### E. 개발자용 정보

- dinosaur id, species id, raw equippedCostumes 등은 개발자 패널로 숨김

## 4. 놀이터 탭 UI 방향

놀이터는 어린이 대상 육성 모바일 게임 앱의 표준을 참고해 최대한 깔끔하게 정리한다.

### 최종 목적

- 공룡과 놀아주는 탭
- 복잡한 수치 조작 화면이 아니라, 짧은 상호작용 화면
- 아이가 “공룡을 돌보고 있다”는 느낌을 받아야 함

### 화면 구조

#### A. 중앙 공룡

- 선택된 공룡이 중앙에 배치
- 배경은 놀이터/잔디/방 같은 부드러운 분위기

#### B. 상호작용 버튼

예:

- 쓰다듬기
- 공 던지기
- 쉬게 하기
- 산책하기

#### C. 리액션

- 버튼을 누르면 공룡이 반응
- “기분이 좋아졌어요!”
- “조금 쉬고 싶어해요.”
- “공룡이 신나게 뛰었어요!”

#### D. 상태 변화

- 행복감/에너지 변화는 작게 표시
- 숫자보다 리액션 중심
- 세부 수치는 우리 공룡 탭에서 확인 가능

#### E. 기준

- 한 화면에 너무 많은 카드 금지
- 모바일 육성 게임처럼 명확한 행동 버튼 중심
- 아이가 바로 이해할 수 있는 문구 사용

## 5. 알 부화장 UI 방향

알 부화장은 우리 공룡 탭과 유사한 구조로 정리한다.

### 최종 목적

- 알이 중앙에 크게 보여야 한다.
- 아이가 알과 교감하고 있다는 느낌을 받아야 한다.
- 부화 아이템 적용이 편해야 한다.
- 보유 중인 알이 여러 개일 경우 좌우 화살표로 넘겨볼 수 있어야 한다.

### 화면 구조

#### A. 중앙 알 영역

- 현재 선택된 알이 중앙에 크게 위치
- hatchProgress 게이지 표시
- 알 이름/종류/희귀도 표시 가능
- 좌우 화살표로 보유 알 전환

#### B. 알 교감

- 알 쓰다듬기
- 알 살펴보기
- 따뜻하게 해주기
- 리액션 문구 표시
- 예: “알이 따뜻해졌어요.”
- 예: “안에서 작은 소리가 들리는 것 같아요!”

#### C. 부화 아이템 영역

- 보유한 부화 아이템이 잘 보여야 한다.
- 예: 따뜻한 돌멩이, 포근한 담요, 반짝 에너지
- 아이템 선택 → 사용 → hatchProgress 증가
- 아이템 수량 표시
- 사용 후 리액션 표시

#### D. 부화 가능 상태

- hatchProgress 100% 도달 시 “부화하기” 버튼 강조
- 부화 후 새 공룡 등장 결과 화면
- 새 공룡은 우리 공룡 탭에서 선택 가능

#### E. 보유 알 선택

- 우리 공룡 탭처럼 좌우 화살표 사용
- 알이 여러 개면 넘겨서 볼 수 있어야 함
- activeEggId 구조 유지

## 6. 상점 UI 방향

상점은 전체 아이템을 한눈에 볼 수 있되, 세부 아이템은 팝업으로 확대해서 아이가 흥미롭게 볼 수 있어야 한다.

### 최종 목적

- 아이템 카드 목록은 단순하게
- 누르면 상세 팝업
- 상세 팝업에서 아이템 설명, 효과, 가격, 구매 버튼이 크게 보임
- 아이가 아이템을 “수집하고 싶다”고 느낄 수 있어야 함

### 화면 구조

#### A. 상점 목록

- 먹이
- 코스튬
- 알
- 부화 아이템
- 카테고리 탭 또는 필터 가능

#### B. 아이템 카드

- 아이템 이미지/아이콘
- 이름
- 가격
- 보유 여부 또는 수량
- 구매 가능/불가 표시

#### C. 아이템 상세 팝업

아이템을 누르면 확대 팝업 표시

팝업 내용:

- 큰 아이템 이미지
- 이름
- 짧은 설명
- 아이가 흥미로워할 텍스트
- 효과
- 가격
- 보유 수량
- 구매 버튼

예:

“따뜻한 돌멩이”

“햇빛을 머금은 따뜻한 돌멩이예요. 알에게 사용하면 안쪽의 아기 공룡이 조금 더 힘을 낼 수 있어요.”

#### D. 구매 후 피드백

- “구매했어요!”
- “코인이 부족해요.”
- 구매 후 수량 즉시 반영

## 7. 도감 UI 방향

도감은 전체 공룡을 볼 수 있고, 각 공룡을 누르면 확대 팝업으로 자세히 볼 수 있어야 한다.

### 최종 목적

- 수집욕을 자극하는 화면
- 발견한 공룡과 아직 발견하지 못한 공룡을 구분
- 누르면 세부 설명이 팝업으로 표시
- 아이가 공룡 세계를 탐험하는 느낌을 받아야 함

### 화면 구조

#### A. 도감 전체 보기

- 공룡 카드 그리드
- 발견한 공룡은 컬러 표시
- 미발견 공룡은 실루엣/물음표 표시
- 보유 여부 표시 가능

#### B. 공룡 카드

- 공룡 이미지
- 이름
- 발견 여부
- 희귀도 또는 특징

#### C. 도감 상세 팝업

공룡 카드를 누르면 확대 팝업 표시

팝업 내용:

- 큰 공룡 이미지
- 이름
- 짧은 설명
- 아이가 흥미로워할 텍스트
- 좋아하는 먹이
- 성격
- 발견 방법 또는 힌트
- 보유 중이면 “우리 공룡으로 보기” 버튼

예:

“트리케라”

“튼튼한 뿔을 가진 용감한 공룡이에요. 친구를 지키는 걸 좋아하고, 훈련을 마치면 아주 신나게 꼬리를 흔들어요.”

#### D. 미발견 공룡 팝업

미발견 공룡을 눌렀을 때:

- 실루엣 크게 표시
- “아직 만나지 못한 공룡이에요.”
- “알을 부화시키면 만날 수 있을지도 몰라요.”
- 너무 많은 정보는 숨김

## 8. 개발자용 정보 분리

현재 기능 테스트용으로 보이는 많은 정보는 최종 UI에서 숨겨야 한다.

개발자 모드로 이동할 것:

- 전체 문제 목록
- 생성된 problems 배열 전체
- stage id
- resolved settings raw 값
- trainingHistory raw 로그
- progressByLevel/progressByStage raw 데이터
- Bluetooth 디버그 로그
- localStorage raw 데이터
- dinosaur id/species id
- egg id
- inventory raw 구조

최종 아이 화면에 남길 것:

- 현재 문제
- 진행률
- 공룡 리액션
- 보상
- 아이템
- 알/공룡/도감의 시각적 정보
- 아이가 이해할 수 있는 짧은 문구

## 9. 공통 팝업 규칙

상점과 도감, 아이템, 공룡, 알 상세 화면은 팝업 또는 모달 방식으로 정리한다.

공통 규칙:

- 배경은 어둡게 또는 흐리게 처리
- 중앙에 큰 카드
- 이미지가 크게 보임
- 설명 텍스트는 짧지만 흥미롭게
- 닫기 버튼 명확
- 주요 행동 버튼 하나만 강조
- 아이가 실수로 너무 많은 설정을 바꾸지 않도록 함

## 10. 탭별 우선순위

리팩터링 우선순위는 아래 순서를 추천한다.

### 1. 훈련장

- 문제 가독성, 한 문제 집중, 보상 화면이 가장 중요

### 2. 우리 공룡

- 육성/먹이/코스튬의 중심 탭

### 3. 알 부화장

- 부화 아이템 사용과 새 공룡 획득 루프

### 4. 상점

- 아이템 구매/확대 팝업

### 5. 도감

- 수집욕 강화/상세 팝업

### 6. 놀이터

- 공룡 교감 콘텐츠 확장
