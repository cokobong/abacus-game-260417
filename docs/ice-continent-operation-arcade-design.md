# 얼음대륙 운영형 아케이드 최종 기획

## 문서 지위와 게임 정의

**이 문서는 얼음대륙 미니게임의 최우선 기획 기준이다.** 현재 잠긴 얼음대륙 지역, 탐험형 Stage 이름과 설명, 유물 이미지 및 공통 저장 구조는 이 게임의 완성을 뜻하지 않는다. 구현 전에는 이 문서의 아케이드 규칙에 맞춰 연결 여부를 다시 결정한다. 이번 문서 작업은 코드·에셋·지역 잠금 상태를 바꾸지 않는다.

> **얼음대륙은 자동으로 돌아가는 빙하 기지를 좌우로 뛰어다니며 얼어붙은 기계, 멈춘 생산라인, 과열, 생물 방해 등을 빠르게 해결하고, 점점 늘어나는 문제의 우선순위를 판단해 목표 생산량을 달성하는 짧은 운영형 아케이드 게임이다.**

Comic Bakery 계열의 현장 복구 리듬을 참고한다. 직접 기계를 배치하거나 재고를 계산하는 게임이 아니다. 용암계곡은 액션·발판, 하늘섬은 회피, 숫자유적은 공간 계획, 심해협곡은 추격·수집, 얼음대륙은 **실시간 운영·멀티태스킹·우선순위**로 구분한다. 조작은 좌우 이동과 상황에 맞는 행동 하나로 시작한다. 한 번의 복구로 생산라인이 다시 움직이는 반응을 크게 보여 주어 아이가 자신의 선택을 이해하게 한다.

## 한 판의 핵심 루프

기지 가동 → 생산라인 자동 생산 → 한 곳에 시각적 문제 발생 → 플레이어가 좌우로 달려가 A로 복구 → 생산 재개 → Stage 후반에 두세 문제가 겹쳐 우선순위를 선택 → 목표 생산량 달성 → 결과 화면.

플레이어가 가만히 있어도 정상 기계는 생산한다. 플레이어는 자원을 직접 캐거나 운반하지 않는다. 생산 순서는 **채굴 → 컨베이어 운반 → 분쇄·에너지 변환 → 저장**이라는 한 줄의 읽기 쉬운 흐름으로 표시한다. Stage에 없는 기계는 배경 장식 또는 흐름의 일부로만 그린다. 정상 생산의 리듬은 눈에 보이는 결정 이동·기계 회전·저장고 숫자로 전달한다. 고장이 나면 관련 구간의 움직임이 느려지거나 멈추고, 수리 직후 같은 구간이 다시 움직인다.

1~2분, 2~3분, 3~4분은 각각 Stage 1/2/3의 **목표 플레이타임**이다. 강제 countdown을 기본 실패 조건으로 쓰지 않는다. 생산 목표는 초안으로 20/40/60개이며 실제 아이 플레이의 중앙값과 재시도율을 보고 조정한다. 초기 생산 속도는 정상 운전 시 목표에 약간 일찍 도달할 수준으로 잡아, 문제 처리 시간이 판의 길이를 결정하게 한다. 플레이가 길어지면 문제 빈도를 낮추고 현재 원인을 강조한다. 자리를 떠나 무기한 방치해도 깨지는 구조가 되지 않도록 전체 정지 실패 규칙을 둔다.

### 상태와 사건의 최소 모델

- 기계 상태는 `RUNNING / WARNING / BLOCKED / RECOVERING`으로 표현한다. 문제 종류는 별도의 원인 ID와 심각도로 구분한다. 같은 기계에 상충하는 두 문제를 동시에 넣지 않는다.
- 라인은 정상 구간마다 짧은 간격으로 생산 단위를 통과시킨다. 완전 정지는 모두 막혔을 때만 기록하며, 일부 문제는 생산 속도만 낮춘다. 숫자 증가와 시각적 생산물이 일치해야 한다.
- 문제 발생기는 Stage별 허용 종류·동시 상한·최소 간격을 지킨다. 스폰 직후 복구할 수 없는 위치, 화면 밖에서 경고가 없는 문제, 이미 실패 직전인 상태의 연쇄 스폰은 금지한다.
- A는 **근처에서 현재 가장 명확한 한 문제**를 처리한다. 범위가 겹치면 가까운 기계와 전면 강조 표시를 우선한다. 짧은 작업 동작 뒤 원인을 제거하고 필요한 후속 상태를 갱신한다. 아이가 버튼을 누르고도 아무 일도 일어나지 않았다고 느끼지 않도록 진행 효과를 즉시 보여 준다.
- 중요한 화면 상태는 `준비 / 진행 / 성공 / 기지 정지 실패 / 중단`으로 구분한다. 종료·재도전·보상 정산은 한 판에 한 번만 일어난다.

## 화면, 카메라, 입력

iPad 세로의 상단에는 생산 목표 `32 / 40`, 기지 상태, 가장 긴급한 문제 방향을 둔다. 가운데는 플레이어와 여러 기계가 놓인 넓은 가로 작업대, 하단 safe-area 안에는 큰 `←`, `→`, `작업 A`를 둔다. Stage 2 이후 B 도구가 검증되면 오른쪽에 작은 `도구 B` 하나만 더한다. 플레이 영역을 여러 층의 공장처럼 보이게 할 수 있지만 **플레이어 이동은 한 줄의 좌우 작업 동선**이다. 높은 위치의 기계도 해당 가로 정비 지점에서 다룬다. 층간 점프·사다리·숨은 이동층을 추가하지 않는다.

Stage 1은 한 화면 또는 거의 한 화면에 세 기계와 문제 위치가 보인다. Stage 2/3은 화면보다 조금 넓은 가로 기지로 확장하고, 카메라가 플레이어를 부드럽게 따른다. 화면 밖 문제는 좌·우 가장자리에 `!`/`!!`와 방향을 보여 준다. 기지 길이 때문에 문제를 찾는 시간이 주된 난이도가 되어서는 안 된다. Stage 3에서도 가장 먼 기계까지의 이동은 짧은 복구 동작 몇 회보다 길어지지 않도록 제한한다.

`←/→`는 누르는 동안 좌우로 이동하고 떼면 멈춘다. A는 근처의 강조된 문제를 해결한다. 수리 시간이 필요하면 길게 누르기보다 한 번 누르면 짧은 작업이 시작되는 방식을 우선 검증한다. 방향 전환은 즉시, 작업 중의 입력 처리와 중단 가능 여부는 시제품에서 결정한다. 문제에 다가갔을 때 상호작용 가능 범위를 넉넉하게 두고 행동 라벨을 `고치기/녹이기/켜기/치우기/쫓기`처럼 상황에 따라 바꿀 수 있다. 키보드는 개발·접근성 보조 입력이다. 향후 Gamepad API의 좌우 축/D-pad, A 작업, B 도구를 같은 입력 명령으로 정규화하되 현재 문서에서는 구현하지 않는다. 게임패드 연결 해제 시 터치 입력은 계속 동작해야 한다.

## 기계와 문제 읽기

기계 후보는 채굴기·컨베이어·분쇄기·히터·발전기·냉각기·저장고·제어판이다. 실제 한 판에는 아래 Stage별 개수만 쓴다. 모든 문제는 **형태 + 색 + 움직임 + 짧은 아이콘**으로 구분한다. 색만으로 위험을 알리지 않는다.

| 문제 | 즉시 보이는 모습 | A 작업 | 생산 영향·우선순위 단서 |
| --- | --- | --- | --- |
| 동결 | 푸른 얼음 껍질, 멈춘 톱니 | 녹이기 | 진행할수록 얼음이 두꺼워지고 속도가 감소 |
| 과열 | 붉은 몸체, 짧은 증기 | 식히기 | 주황→빨강, 오래 두면 해당 기계 정지 |
| 막힘 | 컨베이어 위 큰 얼음덩어리 | 치우기 | 운반이 즉시 정지하므로 긴급 표시 |
| 전원 차단 | 꺼진 전구와 내려간 스위치 | 켜기 | 연결된 기계가 멈춤; Stage 3 원인 후보 |
| 생물 방해 | 펭귄 등이 실제로 기계에 올라탐 | 쫓기 | 행동하고 도망가는 가벼운 방해, 반복 과밀 금지 |
| 기계 고장 | 멈춘 톱니와 작은 연기 | 고치기 | 해당 기계 생산 정지 |
| 저장고 과적 | 차오른 눈금과 넘치는 결정 | 비우기 | 출구 병목; Stage 3 원인 후보 |
| 센서 정지 | 눈보라 표시와 꺼진 센서등 | 재가동 | 후반 확장 후보, 일반 고장과 시각적으로 구분 |

초기 버전에 모든 문제를 넣지 않는다. Stage 1은 전원 차단·막힘·동결만, Stage 2는 과열과 펭귄 방해를 추가한다. 기계 고장·과적·센서 정지는 Stage 3의 체인을 만드는 데 필요한 것만 선별한다. 문제 위치에는 `!` 또는 `!!`를 띄우고 위험도가 높아질수록 노랑→주황→빨강, 움직임도 강해지게 한다. 숫자 초읽기는 기본 HUD에서 숨긴다. `!!`는 **먼저 처리하면 손실을 막을 수 있는 문제**여야 하며 단순 무작위 장식이 아니다.

## 우선순위와 원인→결과

Stage 1은 동시 문제 한 개만 만든다. Stage 2는 최대 두 개로 늘리고 **이동 거리, 남은 허용시간, 생산 영향**이 서로 다르게 한다. 예를 들어 가까운 펭귄을 쫓는 것보다 먼 컨베이어 막힘을 먼저 풀면 생산이 재개된다. 다만 정답 순서가 한 가지만 되지 않게 상황에 따라 둘 다 해결 가능한 여지를 둔다. 우선순위의 피드백은 문제 해결 직후 생산 숫자가 다시 올라가는 것으로 준다. `!!`는 경고 단계가 충분히 지속된 뒤에만 띄워 아이가 이동할 시간을 보장한다.

Stage 3에서 원인→결과 연결은 **최대 2~3단계**, 동시에 활성화된 체인은 한 개를 기본으로 한다. 예시는 `발전기 꺼짐 → 히터 정지 → 파이프 동결 → 컨베이어 정지`와 `저장고 가득 → 컨베이어 정지 → 분쇄기 대기`다. 엄밀하게는 첫 예시가 원인 포함 네 노드이므로 시제품에서는 `발전기 꺼짐 → 히터 정지 → 파이프 동결`까지 세 노드를 하나의 체인으로 쓰거나 후속 컨베이어 정지는 설명 연출로만 둔다. **원인을 먼저 복구하면 파생 문제는 함께 풀리거나 빠르게 회복**되어야 한다. 파생 문제만 수리하면 원인이 남아 재발하지만, 아이가 곧바로 알아볼 수 있게 원인 기계로 시각적 선을 잠깐 보여 준다. 체인 외에는 독립 문제로 단순하게 유지한다. 숨은 고장 그래프, 임의 레시피, 복잡한 전력 수지는 만들지 않는다.

## Stage 구성과 종료 조건

| Stage | 장소·목표 시간 | 기계·동시 문제 | 새 판단 | 생산 목표 초안 |
| --- | --- | --- | --- | --- |
| **1 빙하 연구소** | 거의 한 화면, 1~2분 | 발전기·컨베이어·히터 3개, 동시 1개 | 이동과 A 복구를 익힘 | 20 |
| **2 얼음 광산** | 짧은 횡스크롤, 2~3분 | 4~5개, 동시 최대 2개 | 과열·동결·펭귄 방해 중 먼저 처리할 곳 선택 | 40 |
| **3 고대 빙하 발전소** | 짧은 횡스크롤, 3~4분 | 5~6개, 동시 최대 3개 | 짧은 원인→결과 체인을 먼저 끊음 | 60 |

**성공**은 목표 생산량 도달 즉시 판정한다. 생산물과 목표 HUD가 함께 채워지고 짧은 기지 정상화 연출 뒤 결과 화면을 연다. **실패 추천은 B: 전체 생산라인 완전 정지가 누적 허용시간을 넘는 경우**다. 예를 들어 10~15초의 복구 유예를 Stage별로 조정하고, 정지 중에는 커지는 경고 게이지를 보여 준다. 단일 기계의 속도 저하만으로 실패시키지 않는다. 복구되면 정지 게이지를 해소하거나 크게 되돌려 희망을 준다. 실패 조건 비교: A의 가동률 0은 추상적이고 순간 0 판정이 불공정할 수 있으며, C의 제한시간 미달은 게임을 초읽기 경쟁으로 바꾼다. B는 눈에 보이는 완전 정지와 복구 행동이 직접 연결된다. 실제 유예시간은 아이 테스트로 정한다.

점수·빠른 복구 콤보는 선택 확장이다. 처음에는 생산량만 점수 역할을 한다. 연속 2회 `GOOD`, 3회 이상 `GREAT` 같은 짧은 피드백은 핵심 루프가 재미있다는 확인 뒤 추가한다. 콤보 보너스가 있다면 몇 초간 생산 속도 증가 또는 상한 안의 작은 코인으로 제한한다. 콤보가 실패 판정·생산 목표 이해를 가려서는 안 된다.

## 방해 생물, 도구, 파워업

Stage 2의 대표 생물은 무섭지 않은 펭귄 한 종류다. 기계 위로 올라가 작업을 막고 A로 쫓으면 짧게 물러난다. 같은 자리에 즉시 재등장하지 않는다. 북극여우·설원 새·눈괴물은 후속 시각 변형 후보이며 별도 AI를 모두 만들지 않는다.

B 보조 도구는 Stage 2 이후 최대 한 가지로 시작한다. **휴대 히터**를 첫 후보로 두어 먼 동결을 즉시 푸는 것이 아니라 가까운 동결 작업을 빠르게 마치는 용도로 검증한다. 수리 키트·망치·긴급 스프레이는 대체 후보이며 여러 종류의 재고 HUD를 만들지 않는다. `긴급 점검 모드`는 짧은 이동·수리 속도 증가와 문제 위치 강조, `자동 수리 드론`은 한 기계 복구라는 후속 후보로 남긴다. 첫 시제품에는 B와 파워업을 넣지 않는다.

## 경제·보상·유물 연결 원칙

훈련장 코인 획득 → 얼음대륙 입장 → 짧은 한 판 → 클리어 보상 → 모험맵 복귀라는 공통 흐름을 따른다. **입장료와 정산 상한은 아직 확정하지 않는다.** 다른 지역 수치를 그대로 복사하지 말고 목표 플레이타임·실패율·재도전 비용을 측정한 뒤 지역별 설정으로 결정한다. 코인·아이템·얼음대륙 수집물은 클리어 결과에서만 정산하는 방향을 우선 검토하고, 중단·실패 보상 정책은 경제 Phase에서 확정한다. `runId` 단위 중복 지급을 막고, 실제 차감 비용과 입장 안내 가격을 일치시킨다. 미니게임 반복만으로 훈련장 경제를 대체하지 않게 한다.

Stage 3 클리어 뒤 얼음대륙 유물조각 기회를 연결하는 방안을 검토한다. 현재 `frost_crystal_crown`의 5부품·완성·실루엣 이미지와 공통 유물 진행 필드는 존재하지만, 얼음대륙 Stage 3 실행 및 지급 분기는 없다. 확률과 pity 수치는 이 문서에서 확정하지 않는다. 심해협곡 기획의 37.5%·2회 실패 후 확정은 **얼음대륙에 자동 적용되는 현재 코드 규칙이 아니다.** 공통 `resolveRegionFinalChest()`는 현재 2회 미획득 뒤 70%, 3회 뒤 확정으로 동작하므로, 구현 때 지역별 정책을 명시적으로 선택해야 한다. 최종 유물 복원은 기존 보관소·저장 구조 재사용 가능성을 검증하고 Stage 3 연결 이전에는 잠금 상태를 유지한다.

## 첫 playable prototype의 종료선

**Stage 1 느낌의 한 화면, 약 60~90초**만 만든다. 발전기·컨베이어·히터 세 기계가 자동으로 얼음 결정을 생산한다. 문제는 전원 꺼짐·컨베이어 막힘·파이프 동결 세 가지이고 한 번에 하나만 발생한다. 플레이어는 큰 `←/→`와 A로 해당 기계 가까이 가서 작업한다. 생산 목표 초안은 12~15개로 두고, 완전 정지가 지속되면 실패한다. 고장 위치·A 라벨·정상화가 설명 없이 이해되는지 본다. 목표 달성·실패·재시도 결과까지가 prototype의 끝이다.

이 첫 판에는 Stage 2/3, 동시 문제, 원인 체인, 생물, B 도구, 파워업, 정식 경제·보상·유물, 게임패드, 세밀한 점수·콤보를 넣지 않는다. 성공 판단은 “아이의 첫 판에서 이동·복구·생산 재개가 연결되고, 실패해도 다시 도전할 이유를 이해한다”이다. 기능 수보다 달려가서 고치고 기지가 살아나는 손맛을 본다.
