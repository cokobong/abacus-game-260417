# 주산게임 이미지 스타일 가이드

조사일: 2026-09-08. 목적: 신규 이미지 생성 시 기존 공룡·배경·UI의 일관성을 유지한다. 대표 이미지 11개를 직접 확인한 표본 조사이며, 전체 에셋 품질 검사나 실제 화면 실행 검증은 아니다. 이번 작업은 문서화만 포함한다.

## 1. 기준과 해석

게임의 중심은 6~8세 어린이가 주산을 배우며 함께 키우는 공룡 친구다. 밝고 친근하고 든든한 인상을 유지하며 숫자·문제·주요 버튼의 가독성을 우선한다.

`visual-direction.md`는 단순한 2D·벡터풍을 추천하지만, 실제 대표 공룡은 **둥근 캐릭터 비율에 부드러운 입체 명암과 비늘 질감을 더한 3D 렌더풍 일러스트**다. 이는 제작 도구가 3D였다는 뜻이 아니라 시각적 특징에 대한 관찰이다. 배경과 UI는 붓으로 그린 듯한 캐주얼 판타지 일러스트에 가깝다. 신규 공룡을 갑자기 평면 벡터풍으로 바꾸지 않는다.

새 작업에서는 실제 연결된 같은 종·같은 용도의 이미지를 우선 참고하고, 이 문서의 공통 기준과 조합한다. 폴더명이나 수정 파일명만으로 최신 에셋을 판단하지 않는다. 공룡 연결은 `src/assets/dex/dinosaurs/index.ts`를 확인한다. 예를 들어 crystalo는 `dinosaurs_1`이 아닌 `dino_upgrade`의 파일을 참조한다.

## 2. 공통 시각 특징과 생성 기준

| 항목 | 관찰 및 신규 생성 기준 |
| --- | --- |
| 형태 | 큰 눈, 둥근 주둥이·몸통, 읽기 쉬운 팔다리와 꼬리. 목·뿔·프릴 등 종을 구별하는 특징은 유지한다. |
| 표정 | 눈동자에 명확한 하이라이트, 열린 미소, 호기심·응원·자신감. 성체도 친구 같은 인상을 유지한다. |
| 명암 | 넓고 부드러운 명암과 밝은 하이라이트. 두꺼운 검정 외곽선보다 입체감과 색 차이로 형태를 나눈다. |
| 표면 | 비늘과 무늬는 존재하지만 전체 실루엣과 얼굴이 먼저 보인다. 사진 같은 피부 주름, 젖은 피부, 과도한 거친 질감은 피한다. |
| 색 | 주황·금색·노랑, 청록·하늘색·초록 등 밝은 색과 크림색 배·턱의 조합. 몸체의 주색과 제한된 무늬·포인트로 정리한다. |
| 공포 수위 | 이빨·발톱·뿔 자체를 없애지 않는다. 웃는 입과 부드러운 형태로 표현하고, 피·상처·살점·공격적 포효·공포 조명을 넣지 않는다. |
| 구도 | 도감·육성용은 한 마리 전신, 정면에 가까운 3/4 시점, 발과 꼬리·뿔이 잘리지 않는 배치. 원본의 좌우 방향을 작업별로 지정한다. |
| 단순화 | 실루엣은 단순하고 종 특징은 선명하게, 표면 디테일은 보조적으로. 작은 카드에서도 얼굴과 종이 구분되어야 한다. |

고정 HEX 팔레트는 이번 조사에서 추출하지 않았다. 색명은 시각적 경향이며 정확한 색을 맞춰야 하는 작업에서는 실제 레퍼런스에서 색을 확인한다. 심해나 얼음 테마라도 전체를 검게 만들거나 형광 효과로 뒤덮지 않고 기존 캐릭터의 밝은 얼굴과 명확한 실루엣을 유지한다.

## 3. 아기·청년·성체 표현

아래는 이미지의 `baby / youth / adult` 구분이다. 게임 성장 상태에는 `baby / child / teen / adult`가 있으므로 이미지의 youth를 새 게임 단계로 추가하거나 레벨 조건을 바꾸지 않는다.

| 이미지 단계 | 표현 기준 |
| --- | --- |
| 아기 baby | 머리와 눈이 몸에 비해 크고, 몸은 통통하며 다리는 짧다. 둥근 볼·짧은 주둥이·작고 친근한 자세를 유지한다. 긴목 공룡은 아기여도 긴 목이라는 종 특징을 살린다. |
| 청년 youth | 아기보다 머리 비율을 줄이고 목·몸·다리를 늘려 활동성을 보여준다. 눈과 미소는 계속 친근하게 유지한다. |
| 성체 adult | 더 넓고 단단한 몸통, 굵은 다리, 발달한 종 특징으로 성장감을 준다. 크기 확대만으로 구분하지 않으며 사실적인 포식자로 바꾸지 않는다. |

티라노 3단계에서 아기는 붉은 주황과 짧은 체형, youth/adult는 금빛 주황과 더 긴 체형으로 관찰된다. 시선 방향과 무늬도 완전히 같지는 않다. 이를 모든 종에 강제하지 않는다. **신규 세트 권장:** 눈 색·주색·대표 무늬·뿔 배치를 유지하고 체형을 단계적으로 변화시킨다. 기존 종과의 정확한 색·좌우 방향 통일 여부는 검토 필요다.

## 4. UI·배경과의 조화

- 홈·상점 배경은 따뜻한 목재, 모래색 바닥, 초록 식물, 청록 하늘을 사용한다. 주변부에 소품을 배치하고 중앙·하단에 UI가 놓일 비교적 단순한 공간을 남긴다.
- 버튼은 둥근 모서리, 금빛 테두리, 크림색 내부, 두께감 있는 명암을 가진다. 신규 아이템도 단순한 큰 형태와 부드러운 하이라이트로 어울리게 만든다.
- 코인 같은 보상은 금색·노랑과 제한된 반짝임으로 인지성을 높인다. 공룡의 비늘 디테일을 작은 아이콘까지 그대로 옮기지 않는다.
- 배경보다 캐릭터, 장식보다 문제 숫자와 행동 버튼이 먼저 보이게 한다. 이미지의 실제 사용 크기와 겹치는 UI 영역을 생성 전에 명시한다.
- 기존 홈 배경과 훈련 버튼에는 글자가 포함되어 있다. **신규 범용 에셋 권장:** 글자·가격·수치·로고는 이미지에 넣지 않고 별도 UI로 구성할 수 있도록 여백을 둔다. 기존 에셋 교체 시 글자 분리 여부는 별도 검토하며 이번 문서화에서 변경하지 않는다.

## 5. 배경·파일 규격

| 용도 | 생성 및 검토 기준 |
| --- | --- |
| 공룡·알·아이템 | 합성을 위한 실제 알파 투명 배경 PNG를 기본으로 한다. 흰색·검정색·체커보드를 배경에 그리지 않는다. |
| 전체 화면 배경 | 불투명한 완성 배경. 대상 화면 비율과 UI 배치에 맞추고 캐릭터용 정사각형 규격을 강제하지 않는다. |
| 그림자 | 공룡 주변에 불필요한 바닥·풍경을 넣지 않는다. 기존 crystalo처럼 접지 그림자가 있는 사례도 있으므로 그림자 포함 여부는 대상 화면에 맞춰 지정한다. |
| 크기 | 직접 확인한 티라노 3단계와 업그레이드 crystalo 아기는 모두 1254×1254, 32비트 ARGB이며 모서리 알파가 0이다. 프로젝트 전체의 강제 규격이라는 뜻은 아니다. |
| 여백 | 전체 실루엣을 포함하고 성장 단계끼리 발 기준선·시각적 크기를 비교한다. 권장 시작값은 가장자리 약 5~10% 여백이며 긴 꼬리·날개에는 조정한다. |

생성 도구가 정확한 크기나 알파 출력을 지원하지 않으면 지원 규격으로 원본을 받고 파이프라인 review 단계에서 필요한 변환을 검토한다. 프롬프트에 ‘투명’이라고 썼다는 이유만으로 승인하지 않는다.

**확인된 예외:** `src/assets/ui/training/reward_coin_icon.png`는 24비트 RGB이며 체커보드가 이미지 자체에 보인다. 이 파일은 색·형태 참고용이고 투명 배경 모범 사례가 아니다. 신규 결과는 밝은색·어두운색 바탕에서 가장자리, 흰 테두리, 색 번짐을 검사한다. 업그레이드 crystalo의 테두리와 접지 그림자도 합성 품질 검토 대상이다. 기존 파일 수정은 이번 범위에 포함하지 않는다.

## 6. 레퍼런스 보관 위치 제안

`reference/style_refs/`를 제안한다. `_asset_pipeline`의 5개 고정 단계는 그대로 유지하고 장기 레퍼런스는 별도 보관한다. 이번에는 제안만 하며 이미지 복사나 폴더 생성은 하지 않는다.

폴더를 만들 때 README 또는 CSV에 원본 경로, 참조 역할, 확인 날짜, 주의사항을 기록한다. 무분별하게 모든 이미지를 복제하지 말고 아래 표의 대표 파일을 선정한다. 각 생성 작업에는 같은 종 이미지와 같은 화면 배경·UI 등 2~4개를 선택하고 각각 ‘체형 기준’, ‘색감 기준’, ‘배경 조화 확인’ 역할을 명시한다.

## 8. 신규 이미지 생성 기본 프롬프트

아래 템플릿의 중괄호를 채우고 실제 레퍼런스 이미지를 함께 제공한다. 파일 경로만 적는 것으로 이미지가 도구에 전달된다고 가정하지 않는다.

```text
주산 학습과 공룡 육성 게임에 사용할 {에셋 종류} 1개를 만든다.
대상 화면: {도감/육성/상점/훈련/기타}, 실제 표시 크기: {크기}.
레퍼런스 A는 {동일 종/체형/표정} 기준,
레퍼런스 B는 {같은 화면의 색감/UI} 기준으로 사용한다.

대상: {종 또는 아이템}, 성장 이미지 단계: {baby/youth/adult/해당 없음}.
유지할 정체성: {주색, 눈 색, 배 색, 무늬, 뿔·목·꼬리의 특징}.
포즈와 방향: {3/4 시점, 바라보는 방향, 자세}.
기존 공룡과 어울리는 둥글고 친근한 입체 일러스트.
부드러운 명암과 밝은 하이라이트, 명확한 실루엣.
{단계에 맞는 머리·몸통·팔다리 비율}.
공룡은 큰 눈과 따뜻한 표정, 표면 질감은 얼굴과 형태를 방해하지 않게.
작은 게임 카드에서도 알아볼 수 있게 핵심 특징을 정리한다.

출력: {가로×세로}, {실제 알파 투명 PNG/불투명 배경}.
{전신과 꼬리·발·뿔을 모두 포함/아이템 전체 포함}, 가장자리 여백 확보.
그림자: {없음/약한 접지 그림자}. 글자·로고·워터마크 없음.
사진 같은 피부, 공포 표정, 피와 상처, 공격적 포효,
과도한 날카로움, 형광색 남용, 복잡한 장식, 잘린 신체,
추가 팔다리, 흰 배경이나 체커보드가 그려진 가짜 투명 배경은 제외한다.
```

아이템에는 성장 비율·눈·표정 지시를 빼고 ‘둥근 덩어리, 큰 대표 무늬, 적은 반짝임’을 넣는다. 배경에는 전신·투명 지시를 빼고 다음을 사용한다.

```text
기존 홈·상점과 어울리는 밝고 따뜻한 캐주얼 판타지 게임 배경.
지역: {주제}, 화면 비율: {비율}, 주색: {색 조합}.
UI 영역 {위치}는 낮은 디테일과 안정된 명도로 비워 둔다.
소품은 주변에 배치하고 중앙은 캐릭터와 숫자가 잘 읽히게 한다.
부드러운 회화적 명암과 둥근 자연물, 불투명 배경.
문자·버튼·가격·캐릭터를 합쳐 그리지 않는다. 공포 조명과 과밀 장식은 제외한다.
```

## 9. 검토 및 반영

1. `inbox/<작업 ID>`에 원본과 생성 조건을 보관한다. 파일명·CSV는 [파이프라인 안내](../_asset_pipeline/README.md)를 따른다.
2. review에서 레퍼런스와 나란히 비교한다. 같은 종인지, 단계가 구분되는지, 기존 UI와 색·명암·재질이 어울리는지 확인한다.
3. 전신 잘림·추가 신체·공포 수위·가짜 투명도·테두리 잔상을 검사한다. 실제 표시 크기로 축소해서 가독성도 확인한다.
4. 기존 화면과의 합성 및 텍스트 가독성 확인 후 approved로 분류한다. 확신이 낮은 부분은 CSV notes에 ‘검토 필요’로 남긴다.
5. 승인과 게임 반영은 별개다. 실제 `src/assets` 또는 `public` 반영과 연결 변경은 별도 작업으로 진행하고 검증한다. 이번에는 새 이미지 생성·교체·게임 로직 변경을 하지 않는다.
