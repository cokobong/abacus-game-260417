# 용암계곡 Stage 2: 용암 절벽

검증일: 2026-09-09. 기준 문서: `docs/ADVENTURE_STAGE_RELIC_SYSTEM.md`.

## 1. 기존 Stage 2에서 유지한 코드

- `adventureStageCatalog.ts`의 Stage 선택·150초·확장 아이템 Pool·2~3개 아이템 드롭 구조.
- `lavaStageSegments.ts`의 하단/상단/분기/복귀 구간, 하강 중 발판 착지, 안전한 지상 복귀.
- 기존 체력·체크포인트·일시정지·재시도·완주 보상 정산과 중복 지급 방지.
- Stage 1의 120초, 난이도별 이동 속도·점프 높이·대시 속도·배경·기존 보상 분포.

## 2. 새 배경 연결

- 원본: `src/assets/adventure/lava-valley/background/bg_lava_valley_stage2_lava_cliff.png`.
- Export: `src/assets/adventure/lava-valley/index.ts`의 `lavaCliffBackground`.
- 사용: `LavaPathPrototype.tsx`에서 Stage 2일 때만 선택하고 플레이 전 preload.
- Stage 1은 기존 `lavaValleyAssets.runnerBackground`를 계속 사용한다.

## 3. Stage별 config

- `src/config/adventureStageCatalog.ts`: 이름, 플레이 시간, 아이템 Pool, 아이템 수량.
- `src/config/lavaStageGameplay.ts`: 점프, 대시 쿨타임, 보상 목표 배율, 문양/비밀문/분출 시간과 활성화 여부.
- `src/config/lavaStageSegments.ts`: 발판 배치와 착지 계산.

## 4. 점프 수치

Stage 2는 초기 수직속도 `v / 0.82`, 중력 `g / 0.82²`, 정점 유지시간 `hold × 0.82`를 사용한다. 이론상 최고 높이 `v² / (2g)`는 유지되고 체공시간은 82%가 된다.

| 난이도 | Stage 1 속도/중력/정점 유지(ms) | Stage 2 속도/중력/정점 유지(ms) |
|---|---|---|
| 쉬움 | 101 / 195 / 120 | 123.17 / 290.01 / 98.4 |
| 보통 | 98 / 215 / 100 | 119.51 / 319.75 / 82 |
| 도전 | 96 / 228 / 80 | 117.07 / 339.08 / 65.6 |

좌표는 기존 플레이필드 높이 비율 단위다. 60fps/30fps 이산 계산에서도 가장 높은 18% 발판에 도달하는 것을 테스트했다. 실제 조작으로 상단 착지도 확인했다.

## 5. 대시

Stage 1은 2,000ms, Stage 2는 3,000ms 쿨타임이다. 속도 1.9배, 지속 1,000ms, 감속 복귀 200ms는 유지한다. 버튼의 활성/비활성과 남은 시간 표시도 Stage별 값을 사용한다.

## 6. 문양조각

- 시작 후 18/46/78초에 각각 하나씩, 총 3개 생성한다.
- 발판 높이는 10/14/18%로 높아지며, 첫 두 개는 비교적 낮은 상단 길에 배치한다.
- 작은 HUD에 `문양조각 0 / 3`부터 표시하고 마지막 획득 시 “비밀문이 열렸어요!”를 표시한다.
- ref와 화면 상태에만 보관한다. 보상 payload, 인벤토리, 프로필에 저장하지 않는다.
- 재시작 시 미션·발판·분출 일정·비밀문·보너스 상태를 모두 초기화한다.

## 7. 비밀문

110초에 상단 비밀문이 한 번 등장한다. 문양 3개를 모으고 문 근처에서 점프 중이면 진입한다. 문양이 부족하거나 문을 지나쳐도 일반 길로 완주할 수 있다. 문과 문양은 장애물 피해 판정에서 제외된다.

## 8. 12초 보너스 샛길

별도 화면 전환 없이 기존 스크롤 플레이필드에 상단 길을 유지한다. 진입 시 주변 장애물을 정리하고, 12초 동안 일반 장애물 생성을 멈춘다. 끝에서는 발판 끝이 지나가며 아래의 안전한 길로 떨어진다. 이후 기존 구간 생성이 이어진다.

코인은 1.5초 간격으로 두 개씩 생성하며, 마지막 코인이 도착하기 전에 길이 끝나지 않도록 종료 3초 전부터 생성을 멈춘다.

## 9. 예고형 용암 분출

- 정해진 구간에서 생성되며, 일부는 상단 발판 위에 놓인다.
- 다가오는 지점부터 경고 1.2초 → 실제 분출 1.1초 → 잦아듦 0.45초 → 제거.
- 느낌표와 바닥 표시로 미리 알린다. 실제 분출 단계에만 피해를 준다.
- 기존 용암 이미지와 간단한 CSS opacity/transform을 사용한다. 새 파티클 시스템은 없다.

## 10. 보상 변경

- 목표 배율은 1.25. 플레이 시간의 120→150초 증가를 기본 예산으로 사용하며, 정산 시 다시 1.25배를 곱하지 않는다.
- 일반 코인 간격을 Stage 2에서 1.1배 늘려 보너스 길의 높은 코인 밀도에 예산을 나눈다. 발판마다 무제한으로 별도 코인 묶음을 추가하던 방식은 제거했다.
- 음식/부화 아이템은 기존 Stage 2의 판당 2~3개 계획을 유지한다. 마지막 두 개를 음식·부화 아이템으로 정해 후반 문 주변 시간대에 배치한다. 비밀길에 진입했다고 별도 아이템 추첨을 추가하지 않는다.
- 희귀조각 기대 생성량은 쉬움 0.91→1.14, 보통 1.11→1.40, 도전 1.31→1.65로 약 1.25~1.26배다.
- 일반 길과 비밀길이 같은 희귀조각 생성 계획을 공유하고, 정산도 한 판 최대 3개를 유지한다. 희귀알 가격 15개는 변경하지 않았다.
- 총 보상 체감 20~30%는 초기 튜닝 목표다. 경로 선택·수집 성공률·난수에 따른 장기 플레이 밸런스 측정은 별도로 필요하다.

## 11. Stage 3 해금

기존 `App.tsx`의 `finishAdventureRun` → `completeAdventureStage` → `saveGameState`를 그대로 사용한다. Stage 2 최초 완주는 Stage 3 해금 상태만 저장한다. Stage 3는 `implemented: false`로 실행할 수 없고 강제 이동하지 않는다.

문양 개수는 완주 여부나 Stage 해금 판정에 전달되지 않는다. Stage 3 게임 본체, 유물조각 지급, 오벨리스크는 이번 변경에 추가하지 않았다. Stage 2의 클리어 연출에서는 기존 상자 이미지를 제외했다.

## 12. 성능과 정리

- 이동 좌표는 ref에서 처리하고 DOM transform만 갱신한다.
- 매 프레임 호출하던 React 시간/무적/대시/아이템 setter를 제거했다. 시간은 초 변경 시, 대시 UI는 0.1초 단위 변경 시, 아이템은 생성·제거·분출 단계 변경 시에만 갱신한다.
- 발판은 기존 최대 4개 제한을 유지한다. 일반 아이템 생성은 28개 기준 제한을 확인하며 미션 오브젝트는 총 3개와 문 1개만 예약된다.
- 화면 밖 아이템·발판과 종료된 분출을 제거한다. 만료된 timeout은 목록에서 제거하고 재시작/언마운트 때 남은 예약을 해제한다.
- 구형 Galaxy Tab 실기기 FPS는 측정하지 않았다. PC 브라우저의 동작 확인과 코드 수준의 생성·갱신 제한을 검증했다.

## 14. 검증 결과

- `npm.cmd run lint`: TypeScript 오류 없음.
- `npm.cmd test`: 50개 통과. Stage별 물리, 30/60fps 발판 도달, 문양 초기화/문 진입 조건, 12초 경계, 분출 단계, 희귀조각 상한/확률, 기존 상점·도감·Stage 진행 회귀 포함.
- `npm.cmd run build`: 성공. 첫 시도는 Windows 실행 제한 때문에 esbuild의 상위 폴더 읽기가 차단되어, 권한을 허용한 동일 빌드로 검증했다.
- 실제 브라우저에서 Stage 2 150초 완주, 문양 0→1→2→3, 점프를 통한 비밀문 진입, 같은 화면의 보너스 길과 종료 후 일반 구간 복귀를 확인했다.
- 실제 완주 결과 예: 코인 56, 음식 `dino-cookie` 1개, 부화 아이템 `hatch-spark-energy` 1개. 이 판의 희귀조각은 0개였다. 희귀조각의 확률/상한은 자동 테스트로 확인했다.
- 실패 후 재시작에서 하트 3개·150초·문양 0/3 초기화를 확인했다.
- Stage 1의 기존 배경/120초/점프/대시, 하늘섬 시작 화면, 상점, 5개 도감 카테고리, 모험 지도와 Stage 선택 팝업을 확인했다. 브라우저 오류 로그는 없었다.
- Stage 3 해금·중복 클리어·저장 데이터 JSON 복원은 기존 진행 함수 테스트 및 App 정산/저장 연결을 확인했다. 검증을 위해 실제 사용자 프로필에 Stage 클리어를 기록하지 않았다.
- 문양 0~2개 일반 완주는 미션과 독립적인 종료 조건 및 진행 테스트로 확인했다. 브라우저 완주 사례는 3/3 경로다.
