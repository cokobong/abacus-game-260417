# 목업 리뷰 메모

이 문서는 현재 목업에서 확인한 화면 구조, 유지할 디자인 방향, 아직 구현하지 않을 항목, 다음 단계 체크리스트를 정리한다.

현재 목업의 목적은 완성형 기능 구현이 아니라, 새 기획 방향에 맞는 화면 흐름과 디자인 톤을 확인하는 것이다.

## 0. 목업 확인 완료 기준

이번 목업에서는 아래 사항을 확인 완료한 것으로 본다.

- 기존 공룡 배틀 콘셉트가 아니라 `주산훈련 기반 공룡 육성 / 수집` 방향으로 화면 구조를 전환했다.
- 앱의 핵심 탭은 `훈련장`이며, 주산 문제 풀이와 보상 예시가 첫 번째 흐름으로 보인다.
- `훈련 → 보상 → 알 부화 / 공룡 성장` 루프가 화면에서 드러난다.
- `우리 공룡`, `알 부화장`, `상점`, `도감`, `모험`, `설정` 탭이 최종 기획의 주요 공간으로 분리되어 있다.
- `우리 공룡`에서 `놀이터`로 이동하는 돌봄/상호작용 확장 흐름을 확인했다.
- 전체 톤은 회색 웹 대시보드보다 밝은 키즈 공룡 육성 게임 UI에 가깝게 조정했다.
- Bluetooth Test는 메인 게임 기능이 아니라 설정 안의 `주산 입력 장치 연결 테스트` 영역으로 분리했다.
- Bluetooth Test 패널의 notification 수신값을 훈련장 답 입력칸과 정답 확인 흐름에 연결하는 최소 목업 검증을 진행했다.
- 노트북의 Netlify Deploy Preview 환경에서 FLEDU Bluetooth 연결과 실제 물리 주판 입력을 확인했다.
- 물리 주판 입력값이 훈련장 답 입력칸에 반영되고, 리턴 버튼이 화면의 `정답 확인`과 동일한 채점 흐름으로 동작하는 것을 확인했다.
- 오답 후 주판알을 정답값으로 다시 움직여 리턴 버튼을 눌렀을 때 정답으로 재채점되는 흐름을 확인했다.
- 현재 훈련장 미션/문제 카드는 테스트 편의를 위해 수동 선택할 수 있지만, 최종 구현에서는 정답 처리 후 자동으로 다음 문제로 넘어가야 한다.
- 현재 버튼과 수치는 모두 더미 데이터 기반 목업이며, 실제 저장 / 성장 / 구매 / 보상 로직은 아직 구현하지 않는다.

## 1. 현재 목업에서 확인된 구조

현재 앱은 `주산 공룡 모험`이라는 임시 타이틀을 사용한다.

핵심 루프는 다음 흐름으로 보이도록 구성했다.

```text
훈련장
→ 주산 문제 풀이
→ 코인 / 알 부화 게이지 / 공룡 기분 보상
→ 알 부화장 또는 우리 공룡으로 연결
→ 상점 / 도감 / 모험으로 확장
```

하단 메인 탭은 다음 7개로 정리했다.

- 훈련장
- 우리 공룡
- 알 부화장
- 상점
- 도감
- 모험
- 설정

각 탭의 현재 역할은 다음과 같다.

| 탭 | 현재 목업 역할 |
| --- | --- |
| 훈련장 | 주산 문제, 답 입력, 정답 확인, Bluetooth 리턴 입력 검증, 보상 예시 표시 |
| 우리 공룡 | 대표 공룡, 성장 상태, 먹이주기, 놀이터 이동 표시 |
| 알 부화장 | 알 1개, 부화 진행률, 훈련 보상과 부화 연결 표시 |
| 상점 | 음식 / 코스튬 / 새로운 공룡 관련 아이템 카테고리 표시 |
| 도감 | 해금 / 잠금 공룡 카드 표시 |
| 모험 | 추후 탐험 / 보상 콘텐츠용 더미 맵 카드 표시 |
| 설정 | 문제 설정 목업과 Bluetooth 주산 입력 장치 테스트 패널 표시 |

## 2. 유지할 방향

현재 방향에서 유지할 점은 다음과 같다.

- 공룡 배틀이나 전투가 아니라, 주산훈련 기반 공룡 육성 게임으로 보이게 한다.
- 훈련장이 가장 중요한 핵심 탭이어야 한다.
- 보상은 주산훈련을 대체하지 않고, 주산훈련을 계속하고 싶게 만드는 장치로 둔다.
- 알 부화는 코인만으로 즉시 끝나는 구조가 아니라, 훈련 보상과 연결한다.
- 공룡은 전투 캐릭터가 아니라 함께 돌보고 성장시키는 친구처럼 보이게 한다.
- 상점은 공룡 직접 구매보다 음식, 코스튬, 알 조각, 부화 보조 아이템 중심으로 둔다.
- 모험은 전투 콘텐츠가 아니라 탐험, 보상, 단서 획득 콘텐츠로 확장한다.
- Bluetooth 기능은 게임 콘셉트 전면이 아니라, 주산 입력 장치 연결을 위한 설정 / 개발자 테스트 영역에 둔다.

디자인 방향은 다음을 유지한다.

- 밝은 하늘색 / 초원 / 따뜻한 키즈 게임 톤
- 큰 캐릭터 중심 화면
- 둥근 패널과 두꺼운 버튼
- 코인, 레벨, 도감 진행 같은 게임 HUD
- 사료 가방, 도감 카드, 상점 아이템이 게임 오브젝트처럼 보이는 구성
- 터치 노트북에서 한눈에 이해되는 큰 탭과 버튼

## 3. Bluetooth 실기 테스트 결과

노트북의 Netlify Deploy Preview 환경에서 실제 Bluetooth 주판 입력을 확인했다.

확인된 사항:

- Web Bluetooth API, `navigator.bluetooth`, `getAvailability()`가 정상 동작했다.
- Chrome/Edge 계열 브라우저와 HTTPS Preview 환경에서 FLEDU 기기 연결 테스트가 가능했다.
- Bluetooth Test 패널에서 notification의 raw value, hex, text 로그를 확인했다.
- 물리 주판에서 만든 값이 훈련장 답 입력칸에 반영됐다.
- 리턴 버튼 신호가 `confirm signal received`로 감지됐다.
- 리턴 버튼 수신 시 화면의 `정답 확인` 버튼을 직접 누르지 않아도 같은 채점 흐름으로 연결되는 것을 확인했다.
- 오답 후 주판알을 다시 움직이고 리턴 버튼을 누르는 재시도 흐름을 검증했다.
- 오답 후 정답 재입력 시 이전 입력값, 이전 피드백, React state timing, stale handler 문제로 오답이 반복되던 오류를 수정하고 다시 확인했다.

최종 구현 시 유지할 규칙:

- 물리 주판에는 별도의 초기화 버튼이나 초기화 신호가 없다.
- 사용자는 손으로 주판알을 움직여 값을 만들고, 리턴 버튼으로 현재 배열값을 앱에 보낸다.
- 리턴 버튼은 `값 전송 + 정답확인` 역할을 한다.
- 새 문제 시작 시 앱 내부 답안과 피드백만 비우고, 주판 초기화 신호를 기다리는 상태를 만들지 않는다.
- 새 문제 안내 문구는 `주판알을 답에 맞게 움직인 뒤 리턴 버튼을 눌러주세요.`를 기준으로 한다.
- Bluetooth 리턴 수신 시 방금 파싱한 값을 훈련장 입력칸에 반영하고, 같은 값을 직접 채점 함수에 넘긴다.
- `setInputValue` 이후 React state를 다시 읽어 채점하지 않는다.
- 오답 후에는 같은 문제에서 재시도할 수 있어야 한다.
- 정답 완료 상태에서만 중복 보상과 중복 채점을 막는다.
- 같은 raw/hex 리턴 payload가 아주 짧은 시간 안에 반복 수신되는 경우만 debounce로 막는다.
- Bluetooth 로그와 현재 문제 답안 상태는 분리해서 관리한다.
- Bluetooth 입력 연결은 저장/성장/상점/도감 로직과 직접 결합하지 않는다.
- 현재 목업의 문제 카드 수동 선택은 테스트용 UI이며, 최종 구현에서는 세트 안에서 자동 진행한다.
- 정답이면 짧은 피드백 후 자동으로 다음 문제로 이동한다.
- 오답이면 같은 문제에서 다시 시도할 수 있다.

## 4. 이번 단계에서 구현하지 않을 항목

현재 목업에서는 아래 기능을 구현하지 않는다.

- 실제 저장 기능
- 로그인 / 계정 기능
- 실제 성장 계산 로직
- 실제 EXP / 레벨업 로직
- 실제 코인 지급과 차감
- 실제 상점 구매 처리
- 실제 알 부화 완료 처리
- 랜덤 공룡 획득 로직
- 도감 영구 해금 처리
- 미니게임
- 모험 시간 계산 / 보상 수령 로직
- 결제 기능
- 자동 난이도 조절
- 실제 난이도 커리큘럼 전체 구현
- 완성형 문제 생성 / 세트 결과 정산
- 완성형 Bluetooth 입력 컨트롤러와 세트 진행 로직

현재 들어간 버튼 동작과 피드백은 모두 목업 확인용 더미 동작이다.
Bluetooth 입력과 훈련장 채점 연결도 실기 테스트를 위한 최소 목업 연결이며, 저장/성장/보상 정산과는 아직 결합하지 않는다.

## 5. 배틀 프로토타입 처리 기준

과거의 `ABACUS DINO BATTLE` / 공룡 배틀 프로토타입은 Bluetooth 키 입력 연결과 피드백을 테스트하기 위한 임시 버전으로 본다.

앞으로의 목업과 디자인에서는 다음 요소를 사용하지 않는다.

- 배틀 / 전투 / 보스 / 공격 / 승리 중심 표현
- `ABACUS DINO BATTLE` 타이틀
- 기존 공룡 배틀 시작화면 이미지
- 전투 배경과 공격 / 피격 / 승리 연출

기존 배틀 자산 파일이 프로젝트에 남아 있더라도, 새 목업 UI에서는 참조하지 않는다.
자산 삭제는 별도 정리 단계에서 결정한다.

## 6. 다음 단계

목업 UI와 Bluetooth 주판 입력 테스트가 완료되었으므로, 다음 단계는 실제 세션과 저장 가능한 게임 상태를 만드는 방향으로 진행한다.

우선순위:

1. 데이터 모델 설계
2. 훈련 세션 실제 로직 구현
3. 보상/성장 계산 구현
4. 로컬 저장 구현
5. 상점/도감/놀이터 확장

각 단계는 독립적으로 검증 가능하게 작게 진행한다. Bluetooth 입력은 훈련장 입력 컨트롤러를 통해 연결하되, 저장/성장/상점/도감 로직과 직접 결합하지 않는다.

## 7. 다음 단계 체크리스트

다음 단계에서는 아래 순서로 확인한다.

### 화면 / UX

- 훈련장 화면이 아이에게 가장 먼저 눌러보고 싶은 핵심 탭으로 보이는지 확인한다.
- 주산 문제 영역이 캐릭터 / 장식보다 우선적으로 읽히는지 확인한다.
- 보상 예시가 `훈련 → 보상 → 알 부화 / 성장` 흐름을 충분히 설명하는지 확인한다.
- 우리 공룡 화면에서 대표 공룡, 성장 상태, 먹이주기, 놀이터 이동이 직관적인지 확인한다.
- 알 부화장 화면에서 훈련 보상이 부화 진행으로 이어지는 것이 보이는지 확인한다.
- 상점에서 음식 / 코스튬 / 새로운 공룡 카테고리가 명확히 구분되는지 확인한다.
- 도감의 해금 / 잠금 상태가 아이가 이해하기 쉬운지 확인한다.
- 모험이 전투가 아니라 탐험 / 보상 콘텐츠로 느껴지는지 확인한다.
- 설정 안의 Bluetooth Test가 메인 게임 화면을 방해하지 않는지 확인한다.
- 훈련장 문제 카드를 수동으로 고르는 현재 흐름은 테스트용임을 전제로 보고, 최종 구현에서는 정답 후 자동 다음 문제 진행이 자연스러운지 확인한다.

### 기술 / 구조

- 목업 데이터가 커지기 시작하면 `src/data` 아래로 분리할지 검토한다.
- 훈련장 입력 흐름을 실제 문제 생성 로직과 연결하기 전에 입력 컨트롤러 구조를 먼저 정리한다.
- 최종 훈련 세션에서는 정답 후 자동 다음 문제 이동, 오답 후 같은 문제 재시도, 문제 전환 시 내부 입력/피드백/confirm guard 초기화가 필요하다.
- Bluetooth Test 패널에서 실제 FLEDU notification 로그를 노트북에서 확보한다.
- 실제 UUID / characteristic / packet 구조가 확정되기 전까지 Bluetooth 로직은 게임 보상 로직과 결합하지 않는다.
- 물리 주판에는 별도 초기화 버튼이나 초기화 신호가 없으며, 리턴 버튼은 현재 주판알 배열값 전송과 정답 확인 역할을 한다.
- Bluetooth 리턴 수신 시 방금 파싱한 값을 직접 채점 함수에 넘겨 React state timing 문제를 피한다.
- 설정값 저장은 별도 단계에서 `localStorage` 기반으로 작게 구현한다.

### 실기 테스트

- 집 PC에서는 Bluetooth adapter unavailable 안내가 정상적으로 보이는지 확인한다.
- 실제 Bluetooth 연결 성공 여부는 과거 연결 성공했던 Windows 노트북에서 확인한다.
- 노트북 테스트 시 `FLEDU` 이름 필터와 전체 기기 검색 테스트를 모두 확인한다.
- notification 수신 시 raw value, hex string, text decode 결과를 기록한다.
- 리턴 버튼 수신 시 parsed number가 훈련장 입력칸에 반영되고, 화면 버튼 없이 즉시 같은 채점 로직으로 정답/오답 처리되는지 확인한다.
- 오답 후 주판알을 다시 움직여 리턴 버튼을 누르면 새 값으로 재채점되는지 확인한다.
- 정답 완료 후 같은 리턴 신호가 중복 수신되어도 보상/정답 처리가 한 번만 발생하는지 확인한다.

## 8. 다음 구현 후보

목업 방향이 확정되면 다음 구현 후보는 아래 순서가 적당하다.

1. 훈련장 문제 설정 목업 정리
2. 실제 문제 생성 로직과 훈련장 UI 연결
3. 화면 키패드 또는 간단한 입력 컨트롤러 추가
4. Bluetooth 입력을 훈련장 입력 컨트롤러에 정식 연결
5. 훈련 결과 보상 계산 더미 구조 정리
6. `GameState` 데이터 구조 초안 작성
7. localStorage 저장 / 복원 최소 구현

각 단계는 독립적으로 검증 가능하게 작게 진행한다.

## 9. 훈련장 로직 분리 완료 메모

`feature/training-session` 브랜치에서 훈련장 로직 분리를 완료했다.

완료한 내용:

- `TrainingProblem` / `TrainingSession` / `useTrainingSession` 구조를 도입했다.
- 목업 더미 문제를 별도 데이터 구조로 분리했다.
- 현재 문제는 index 기반으로 진행한다.
- 정답이면 짧은 피드백 후 자동으로 다음 문제로 이동한다.
- 오답이면 같은 문제에서 재시도할 수 있다.
- 마지막 문제까지 풀면 세트 완료 상태를 표시한다.
- Bluetooth 리턴 입력은 방금 수신한 `parsedValue`로 즉시 채점하는 규칙을 유지한다.
- `setInputValue` 이후 React state를 다시 읽어 채점하지 않는 원칙을 유지한다.

다음 작업:

- 보상 계산 더미 구조를 훈련 세션 결과와 연결한다.
- 보상 연결 범위는 코인, 알 부화 게이지, 공룡 기분/성장 상태 목업 반영까지로 제한한다.
- 실제 저장 기능, 상점 구매, 도감 해금은 아직 보류한다.
