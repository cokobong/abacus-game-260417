# 주산 문제 난이도 Progression

이 문서는 주산 문제의 난이도 progression과 부모/관리자 난이도 설정 방식을 정리한다.
문제 난이도는 공룡 레벨이나 게임 보상 단계가 아니라, 아이의 실제 주산 학습 진도에 맞춰 관리한다.

## 1. 난이도 판단 기준

이 게임의 문제 난이도는 단순히 숫자 자릿수만으로 정하지 않는다.
난이도는 다음 요소의 조합으로 판단한다.

- 숫자 자릿수
- 5의 보수 사용 여부
- 10의 보수 사용 여부
- 받아올림/받아내림 여부
- 항의 개수
- 속도 압박

예를 들어 같은 1자리 수 문제라도 `2 + 3`과 `8 + 7`은 주산 학습 난이도가 다르다.
`8 + 7`은 10의 보수와 받아올림 개념이 들어가므로 더 높은 단계로 본다.

## 2. 공룡 레벨과 문제 난이도 분리

공룡 레벨과 문제 난이도는 서로 직접 연결하지 않는다.

- 공룡 레벨: 보상, 성장, 애착, 수집 시스템
- 문제 난이도: 아이가 실제로 배운 주산 개념과 교재 진도

공룡 레벨이 높아도 아이가 아직 2자리 받아올림을 배우지 않았다면, 문제 난이도는 낮은 단계로 유지할 수 있어야 한다.
반대로 공룡 레벨이 낮아도 부모가 허용한 학습 단계 안에서는 높은 난이도 문제를 출제할 수 있다.

## 3. 현재 기본 전제

초기 설계 기준의 학습 상태:

- 아이는 1자리수 계산은 대부분 학습 완료
- 2자리수 계산을 이제 시작
- 보수 개념, 올림수, 받아올림/받아내림은 교재 진도에 맞춰 단계적으로 올라감

따라서 초기 기본 설정은 1자리 복습과 2자리 낮은 단계 진입을 모두 고려한다.

## 4. 난이도 Stage 초안

| Stage | 이름 | 주요 조건 | 예시 | 메모 |
| ---: | --- | --- | --- | --- |
| 1 | 1자리 기본 덧셈 | 합이 9 이하, 5의 보수/10의 보수 없음 | `2+3`, `4+1`, `6+2` | 기본 복습 |
| 2 | 1자리 기본 뺄셈 | 받아내림 없음 | `8-3`, `6-2`, `9-4` | 기본 복습 |
| 3 | 5의 보수 덧셈 | 5의 보수 사용 | `4+3`, `3+4`, `2+4` | 속도보다 정확도 우선 |
| 4 | 5의 보수 뺄셈 | 5의 보수 사용 | `6-3`, `7-4`, `8-4` | 정확도 우선 |
| 5 | 10의 보수 덧셈 / 받아올림 | 10의 보수, 받아올림 | `8+7`, `9+6`, `7+5` | 속도 보상 약화 |
| 6 | 10의 보수 뺄셈 / 받아내림 | 10의 보수, 받아내림 | `13-7`, `12-5`, `15-8` | 정확도 우선 |
| 7 | 2자리 + 1자리, 올림 없음 | 일의 자리 합 9 이하 | `23+4`, `51+6`, `72+3` | 2자리 입문 |
| 8 | 2자리 - 1자리, 내림 없음 | 일의 자리에서 바로 뺄 수 있음 | `28-4`, `56-3`, `79-5` | 2자리 입문 |
| 9 | 2자리 + 1자리, 받아올림 있음 | 일의 자리 받아올림 | `27+6`, `48+7`, `59+8` | 중급 |
| 10 | 2자리 - 1자리, 받아내림 있음 | 일의 자리 받아내림 | `32-7`, `45-8`, `61-9` | 중급 |
| 11 | 2자리 + 2자리, 올림 없음 | 각 자리 올림 없음 | `23+14`, `52+31`, `64+25` | 2자리 확장 |
| 12 | 2자리 + 2자리, 받아올림 있음 | 일의 자리 또는 십의 자리 받아올림 | `27+36`, `48+27`, `59+18` | 정확도 중심 |
| 13 | 2자리 - 2자리, 받아내림 없음 | 각 자리 내림 없음 | `58-24`, `76-31`, `94-52` | 2자리 뺄셈 확장 |
| 14 | 2자리 - 2자리, 받아내림 있음 | 받아내림 필요 | `52-28`, `71-36`, `84-47` | 높은 난이도 |
| 15 | 세 수 연산 | 항 3개 이상, 주판 상태 유지 | `3+5+2`, `24+13+2`, `35-12+6` | 작업 기억과 주판 상태 유지가 핵심 |

Stage는 문제 생성 범위를 설명하는 기준이며, 화면에 반드시 숫자 그대로 노출할 필요는 없다.
아이에게는 `쉬운 복습`, `새로 배우는 문제`, `도전 문제`처럼 부드럽게 표현한다.

## 5. 학습 모드 구조

### 복습 모드

- 이미 배운 단계 반복
- 정확도 유지와 속도 향상 중심
- 속도 보상 정상 적용
- 아이가 자신감을 얻는 용도

### 학습 중 모드

- 현재 교재 진도 단계
- 정확도 중심
- 속도 보상 약화
- 오답이 많아도 실패 패널티를 강하게 주지 않음

### 도전 모드

- 배운 단계를 섞어 실력 확인
- 성공 시 보너스
- 실패 패널티 없음
- 부모가 허용한 범위에서만 사용

## 6. 부모/관리자 난이도 설정 방식

문제 난이도는 Stage 하나만 선택하는 방식으로 제한하지 않는다.
부모가 현재 아이가 배운 개념을 체크박스/옵션 형태로 선택할 수 있게 설계한다.

부모 설정 예시:

- 1자리 덧셈
- 1자리 뺄셈
- 5의 보수 덧셈
- 5의 보수 뺄셈
- 10의 보수 덧셈 / 받아올림
- 10의 보수 뺄셈 / 받아내림
- 2자리 + 1자리, 올림 없음
- 2자리 - 1자리, 내림 없음
- 2자리 + 1자리, 받아올림 있음
- 2자리 - 1자리, 받아내림 있음
- 2자리 + 2자리, 올림 없음
- 2자리 + 2자리, 받아올림 있음
- 2자리 - 2자리, 받아내림 없음
- 2자리 - 2자리, 받아내림 있음
- 세 수 연산

부모가 체크한 항목 안에서만 문제를 생성한다.

예시:

```text
"2자리 + 1자리, 올림 없음"만 체크
→ 해당 유형 문제만 출제
```

```text
"1자리 복습"과 "2자리 올림 없음"을 함께 체크
→ 두 유형을 섞어 출제
```

## 7. 문제 생성 모드

### 1. 선택 범위 반복 모드

- 부모가 체크한 유형만 반복 출제
- 현재 교재 진도에 맞춘 기본 모드
- 특정 개념을 충분히 반복하기 좋음

예시:

```text
체크된 유형: 2자리 + 1자리, 올림 없음
출제: 23+4, 51+6, 72+3
```

### 2. 복습 섞기 모드

- 현재 학습 유형 70%
- 이전 복습 유형 30%
- 이미 배운 개념을 잊지 않게 유지

예시:

```text
현재 학습: 2자리 + 1자리, 올림 없음
복습 유형: 1자리 덧셈, 1자리 뺄셈
출제 비율: 현재 70%, 복습 30%
```

### 3. 도전 소량 추가 모드

- 현재 학습 유형 80%
- 바로 다음 단계 유형 20%
- 단, 부모가 허용한 경우에만 사용

예시:

```text
현재 학습: 2자리 + 1자리, 올림 없음
도전 유형: 2자리 + 1자리, 받아올림 있음
출제 비율: 현재 80%, 도전 20%
```

도전 유형에서 틀려도 실패 패널티를 주지 않는다.
도전은 실력 확인과 다음 개념 준비를 위한 맛보기로만 둔다.

## 8. 속도 보상 조정

속도 보상은 문제 유형과 학습 모드에 따라 다르게 적용한다.

| 유형 | 속도 보상 |
| --- | --- |
| 복습 유형 | 정상 적용 |
| 현재 학습 유형 | 정확도 우선, 속도 보상 약화 |
| 도전 유형 | 성공 보너스는 있지만 실패 패널티 없음 |

원칙:

- 보수 개념, 받아올림, 받아내림을 배우는 중에는 속도를 강하게 요구하지 않는다.
- 복습 단계에서는 속도 보상이 집중력 향상 보너스로 작동할 수 있다.
- 도전 문제는 맞히면 기분 좋은 보너스를 주되, 틀렸다고 손해를 주지 않는다.

## 9. 자동 난이도 추천

자동 추천은 가능하지만, 자동으로 문제 범위를 넓히지는 않는다.

추천 기준:

| 최근 기록 | 추천 |
| --- | --- |
| 최근 5세트 평균 정답률 90% 이상 + 평균 속도 B 이상 | 다음 단계 열기 제안 |
| 최근 5세트 평균 정답률 80% 이하 | 현재 단계 유지 또는 이전 단계 복습 추천 |
| 정확도는 높지만 속도가 느림 | 승급보다 복습 모드 추천 |
| 속도는 빠르지만 오답이 많음 | 난이도 유지, 정확도 우선 안내 |

제안 문구:

```text
최근 훈련이 안정적이에요.
다음 개념을 열어볼까요?
```

앱은 부모 승인 없이 새 문제 유형을 활성화하지 않는다.

## 10. 부모 설정 저장값 예시

추후 구현 시 저장할 수 있는 형태의 예시다.
정확한 타입과 필드명은 구현 단계에서 조정할 수 있다.

```ts
problemDifficultySettings: {
  enabledConcepts: [
    "single_digit_add_basic",
    "single_digit_sub_basic",
    "two_digit_plus_one_no_carry"
  ],
  currentConcepts: [
    "two_digit_plus_one_no_carry"
  ],
  reviewConcepts: [
    "single_digit_add_basic",
    "single_digit_sub_basic"
  ],
  challengeConcepts: [],
  generationMode: "selected_only" | "review_mix" | "small_challenge";
  autoRecommendationEnabled: true;
  requireParentApprovalForNewConcept: true;
}
```

## 11. 보상 규칙과 연결

보상 계산의 기본 원칙은 `game-rule.md`를 따른다.
다만 문제 난이도와 학습 모드에 따라 속도 보상과 도전 보너스는 조정한다.

- 복습 모드: 속도 보상 정상 적용
- 학습 중 모드: 정확도 보상 중심, 속도 보상 약화
- 도전 모드: 성공 시 보너스 크지만 실패 패널티 없음

## 12. 초기 구현 범위

1차 구현:

- 부모가 문제 유형을 체크박스로 선택
- 선택 범위 반복 모드
- 공룡 레벨과 문제 난이도 분리
- 문제 생성 시 체크된 유형 안에서만 출제

2차 구현:

- 복습 섞기 모드
- 최근 5세트 기반 추천 문구
- 속도 보상 조정

후속 구현:

- 도전 소량 추가 모드
- 교재 진도 프리셋
- 아이별 약한 유형 자동 추천
- 부모 승인 기반 새 개념 활성화
