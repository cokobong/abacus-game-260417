# 화면 흐름

## 0. 사용 환경 전제

초기 버전은 일반 모바일 앱이 아니라 터치 기능이 있는 노트북에서 고정적으로 실행하는 브라우저 기반 로컬 웹앱으로 사용한다.

- 로컬 개발 시 `localhost`에서 실행
- 배포 시 Netlify 또는 유사한 HTTPS 웹 배포 환경 사용
- 추후 PWA 형태로 설치형 앱처럼 전환 가능
- 앱 재실행 후 설정, 코인, 공룡, 알, 도감 상태를 복원
- 블루투스 주판 연결은 브라우저/기기 상태에 따라 설정탭에서 다시 확인

## 1. 기존 학습 흐름

시작 화면
→ 20문제 풀이 화면
→ 결과 화면
→ 공룡 키우기 화면
→ 상점 화면
→ 다시 시작 화면 또는 다음 세트

## 2. 화면별 역할

### 시작 화면
- 게임 시작
- 현재 코인 확인
- 대표 공룡 확인

### 문제 풀이 화면
- 20문제 풀이
- 정답 시 코인 획득 예정 표시
- 속도 보너스 표시
- 블루투스 주판 입력을 기본 입력으로 사용
- 블루투스 주판을 사용할 수 없을 때는 터치 화면 키패드 사용
- 마우스 입력은 보호자/개발자 보조 입력으로 사용
- 키보드 입력은 개발/디버그 보조용으로 제한

### 결과 화면
- 20문제 결과 요약
- 최종 코인 정산
- 성장 결과 확인

### 공룡 키우기 화면
- 먹이 주기
- 경험치 확인
- 레벨 확인

### 상점 화면
- 먹이 구매
- 코스튬 구매
- 새 공룡 직접 구매가 아니라 알 또는 알 조각 구매

## 3. 새 탭 기반 흐름

새 구조에서는 20문제 학습 루프를 유지하되, 학습 밖의 공간을 탭으로 정리한다.

```text
홈 또는 시작 화면
→ 문제 풀이
→ 결과/보상 정산
→ 상점에서 알/알 조각 구매 또는 모험 보상 획득
→ 부화방에서 알 등록과 부화 진행
→ 부화 완료 후 도감 해금
→ 놀이터/도감/모험/상점으로 확장
```

하단 탭 후보:

- 부화방
- 놀이터
- 도감
- 모험
- 상점

터치 노트북 기준으로 하단 탭은 손가락으로 누르기 쉬운 크기와 간격을 확보한다.
탭 이동은 드래그보다 탭 중심으로 설계한다.

## 4. 탭별 화면 역할

### 부화방

- 알 상태 확인
- 부화 게이지 확인
- 문제 풀이 세트 성공으로 부화 게이지 증가
- 부화 보조 아이템과 미션 보상 반영
- 부화 완료 시 캐릭터 획득
- 알 구매/등록 직후에는 공룡 이름을 공개하지 않음
- 부화 중에는 실루엣, 알 무늬, 발자국, 울음소리 같은 단서 표시
- 부화 완료 시 알 카테고리 안에서 랜덤으로 등장한 공룡 공개
- 먹이는 부화 진행이 아니라 부화 후 성장/친밀도 화면에서 사용

### 놀이터

- 부화한 캐릭터와 상호작용
- 기분, 친밀도, 간단한 놀이 확인
- 먹이 또는 장난감 사용

### 도감

- 발견한 알/캐릭터/진화형/아이템 기록
- 미발견 캐릭터 실루엣 표시
- 발견 조건, 희귀도, 진화 조건 힌트 확인
- 알 구매 시점이 아니라 부화 완료 시점에 공룡 카드 정식 해금
- 알 등록 단계에서는 `미확인 알`, `일반 알`, `희귀 알` 정도만 표시

### 모험

- 캐릭터 선택
- 지역 선택
- 일정 시간 뒤 보상 획득
- 코인, 먹이, 장난감, 희귀 알 조각 획득 가능
- 알 조각은 특정 공룡 즉시 해금이 아니라 알 획득/부화 루프로 연결

### 상점

- 기본 아이템 구매
- 먹이, 장난감, 꾸미기 아이템 확인
- 공룡 직접 구매 대신 일반 알, 희귀 알, 특별 알 또는 알 조각 구매
- 알 구매 화면에서는 공룡 이름을 공개하지 않고 카테고리와 미확인 상태만 표시
- 초기에는 아이템 수를 3~5개 정도로 제한

## 5. 상점에서 알 구매 후 부화방 이동 흐름

상점에서 알이나 알 조각을 얻은 뒤에는 부화방으로 이어지는 흐름을 제공한다.

```text
상점
→ 일반 알/희귀 알/알 조각 선택
→ 구매 또는 교환
→ "부화방으로 이동" 안내
→ 부화방에서 알 등록
→ 부화 진행
→ 부화 완료
→ 공룡 공개
→ 도감 정식 해금
```

화면 표시 원칙:

- 상점에서는 `일반 알`, `희귀 알`, `특별 알`처럼 카테고리 단위로 보여준다.
- 구매 직후에도 공룡 이름과 정식 이미지는 공개하지 않는다.
- 부화방에서는 알 무늬와 힌트를 보여주되, 정답처럼 후보 공룡 목록을 모두 보여주지 않는다.
- 도감에는 부화 완료 후 정식 카드가 열린다.

## 6. 부화장 진행 흐름

부화장은 알을 등록하고 문제 풀이 성취를 확인하는 공간이다.
단순히 시간이 지나면 부화하는 방치형 구조가 아니라, 문제 풀이 세트 성공이 누적되어 부화가 진행된다.

```text
부화방에서 알 등록
→ 문제 풀이 화면으로 이동
→ 20문제 세트 완료
→ 성공 조건 확인
→ 부화 게이지 증가
→ 진행률에 따라 알 그래픽과 힌트 변경
→ 필요 시 부화 보조 아이템 사용
→ 조건 충족 후 100% 도달
→ 부화 연출
→ 공룡 공개
→ 도감 정식 해금
```

알 종류별 화면 안내 예시:

| 알 종류 | 화면에 보여줄 목표 |
| --- | --- |
| 기본 알 | 문제 3세트 성공 |
| 일반 알 | 문제 10세트 성공 |
| 희귀 알 | 문제 25세트 성공 + 부화 보조 아이템 |
| 특별 알 | 문제 50세트 성공 + 모험 보상 또는 특정 미션 |
| 전설 알 | 장기 업적 조건 |

- 부화 보조 아이템은 `즉시 부화` 버튼처럼 보이지 않게 한다.
- 보조 아이템 사용 후에도 문제 풀이 세트 성공이 필요하다는 안내를 유지한다.
- 부화 진행률이 75%, 90%에 가까워질수록 힌트가 조금 더 강해진다.

## 7. 문제 풀이 입력 흐름

입력 방식은 다음 우선순위로 설계한다.

```text
블루투스 주판 입력
→ 터치 화면 키패드 입력
→ 마우스 입력
→ 키보드 입력은 개발/보조용
```

블루투스 주판 입력:

```text
아이가 물리 주판에서 값 만들기
→ 주판 확인 버튼 누르기
→ 앱이 현재 주판 값을 정답 입력칸에 반영
→ 화면의 "입력" 버튼을 누른 것과 동일하게 자동 제출
```

터치 화면 키패드 입력:

```text
블루투스 주판 사용 불가
→ 화면 숫자 키패드를 터치
→ 정답 입력칸에 값 표시
→ 화면의 "입력" 버튼 터치
→ 정답 제출
```

오입력 방지 원칙:

- 숫자 버튼과 제출 버튼을 분리한다.
- `입력`, `취소`, `나가기`, `설정` 버튼은 위치와 색상으로 명확하게 구분한다.
- 숫자 키패드 버튼은 최소 56px 이상을 권장한다.
- 주요 CTA 버튼은 최소 64px 이상을 권장한다.
- 키보드 입력은 아이의 기본 흐름이 아니라 개발/보조용으로 둔다.

## 8. 앱 재실행 후 복원 흐름

로컬 저장을 사용해 앱을 다시 열어도 진행 상태가 이어져야 한다.

```text
앱 실행
→ 로컬 저장 데이터 확인
→ 설정값, 코인, 아이템, 공룡, 알, 도감 상태 복원
→ 홈 또는 마지막 주요 화면 표시
→ 설정탭에서 블루투스 주판 연결 확인
→ 학습 시작
```

- 저장 데이터가 없으면 기본 상태로 시작한다.
- 저장 데이터가 깨졌거나 읽을 수 없으면 기본값으로 복구한다.
- 블루투스 주판은 자동 복원을 보장하지 않고, 사용자가 설정탭에서 연결 상태를 확인한다.
## Local Dev Port Policy

- Run the local dev server with `npm run dev`.
- Open the app at `http://localhost:3000`.
- Port `3000` is the only supported local dev server port for this project.
- Vite must not auto-fallback to another port; if port `3000` is busy, stop the existing process and run `npm run dev` again.
