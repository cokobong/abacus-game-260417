# Touch/Tablet UI Guidelines

## 1. 기준 기기

- 1차 기준: 터치 가능한 노트북 가로 화면
- 2차 기준: 태블릿/패드 가로 화면
- 보조 입력: 마우스/트랙패드
- 핵심 사용자는 어린이이며, 마우스 사용이 미숙할 수 있다.

## 2. 기본 원칙

- 마우스 클릭 중심이 아니라 손가락 터치 중심으로 설계한다.
- hover에 의존하지 않는다.
- 작은 텍스트 링크를 만들지 않는다.
- 주요 버튼은 크고 명확해야 한다.
- 하단 탭바는 항상 고정한다.
- 팝업과 하단 탭바가 겹치지 않아야 한다.
- 전체 페이지 스크롤은 최소화하고, 필요한 영역만 내부 스크롤한다.

## 3. 터치 크기 기준

- 일반 터치 버튼 최소 높이: 56px 이상
- 주요 액션 버튼: 64~72px 이상
- 닫기 버튼, 이전/다음 버튼은 크게 만든다.
- 카드 간격은 손가락 터치를 고려해 넉넉하게 둔다.
- 아이가 실수로 다른 버튼을 누르지 않게 간격을 확보한다.

## 4. 스크롤 정책

전체 화면이 길게 스크롤되는 구조를 피한다.

권장 구조:

- 상단: 탭 제목/요약
- 중앙: 핵심 콘텐츠
- 하단: 고정 탭바
- 목록이 많은 경우 해당 목록 영역만 내부 스크롤

예:

- 상점: 아이템 grid 영역만 내부 스크롤
- 우리 공룡: 먹이/코스튬 패널만 내부 스크롤
- 알 부화장: 부화 아이템 패널만 내부 스크롤
- 도감: 서식지별 카드 영역만 스크롤 또는 페이지 전환
- 훈련장: 가능하면 스크롤 없이 현재 문제 1개 중심

## 5. 탭별 UI 방향

### 훈련장

- 스크롤 없이 현재 문제 1개가 중심
- 문제, 정답 피드백, 공룡 리액션이 한 화면에 들어와야 한다.

### 우리 공룡

- 공룡 메인 카드가 가장 크게 보인다.
- 먹이/코스튬은 옆 패널 또는 하단 패널에 둔다.
- 아이템 목록만 내부 스크롤한다.

### 알 부화장

- 알 메인 카드가 가장 크게 보인다.
- 부화 아이템 목록은 별도 패널에서 내부 스크롤한다.
- 부화 결과 팝업은 하단 탭바와 겹치지 않는다.

### 상점

- 카테고리 탭은 상단에 고정한다.
- 아이템 목록 영역만 스크롤한다.
- 상세 팝업은 화면 높이를 넘지 않게 하고 내부 스크롤을 허용한다.
- 구매 버튼은 항상 보이게 한다.

### 도감

- 전체 24종을 한 번에 길게 나열하지 않는다.
- 4개 서식지 x 6종 기준으로 서식지별로 나누어 보여준다.
- 발견/미발견 카드는 크게 터치 가능해야 한다.
- 상세 팝업은 감상 중심으로 구성한다.

### 모험

- 모험 지역 카드는 3~4개 정도로 한 화면 안에 들어오게 한다.
- 결과 팝업은 크고 명확하게 보여준다.

## 6. 팝업/모달 원칙

- 모달은 화면 전체 높이를 넘지 않는다.
- max-height를 설정하고 내부 스크롤을 허용한다.
- 하단 탭바와 겹치지 않도록 padding-bottom 또는 safe area를 고려한다.
- 닫기 버튼은 크고 명확하게 한다.
- 구매/확인/이동 버튼은 항상 눈에 보여야 한다.

## 7. 반응형 기준

기본 기준은 가로형 태블릿/노트북이다.

넓은 화면:

- 2~3열 레이아웃 사용 가능
- 메인 콘텐츠 + 보조 패널 구조

좁은 화면:

- 1열 또는 2열로 축소
- 보조 패널은 아래로 이동
- 하단 탭바 유지

## 8. 앞으로의 코드 반영 방향

- CSS에서 touch-first spacing 기준을 변수화할 수 있으면 좋다.
- 예: `--tap-size`, `--bottom-nav-height`, `--screen-padding`
- 각 screen 컴포넌트는 전체 페이지 스크롤보다 내부 패널 스크롤을 우선한다.
- modal은 공통 패턴을 맞춘다.
- 하단 탭바 높이를 고려한 safe-area class를 만든다.
